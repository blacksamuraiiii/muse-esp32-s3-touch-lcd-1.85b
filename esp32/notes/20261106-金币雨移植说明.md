# 金币雨移植说明（2026-11-06）

第五个小游戏：金币从场地顶掉落，毛毛在场地底接住。效果图 v9（`catch-coins-mockup-v9-start.png` /
`-over.png`）已由用户拍板。开发分支 `feat/goldrain-20261106`，已于 2026-11-06 合入 main，随 **1.5.1 正式版** 发布（原打算发 1.6 测试版，用户决定改回 1.5.1）。

## 玩法与经济

- 30 秒一局，**没有命**：接金币 +1 分，接炸弹 **−5 分**（积分可以变负数，局内不截断）；炸弹不会提前结束游戏，30 秒打满才结束；掉出底边的金币/炸弹都不扣分。
- 掉落速度（用户要求“不要太快”）：90 px/s 起步，每秒 +4，上限 150 px/s。生成间隔 950 ms 起步，每秒 -10 ms，下限 600 ms；同时最多 6 个；炸弹概率 15%。
- 经济与蛇/地鼠完全相同：开局扣 5（`PET_FEE`，金币 <5 拒绝并提示“金币不够（需 5 枚）”），结束时积分 1:1 兑金币、**上限 10、下限 0**（负分兑 0，不会倒扣；`muse_goldrain_settle_score()` 先把负分截到 0 再调 `muse_pet_round_coins()`——后者是 `uint32_t`，负分不截会 wrap 成天文数字），HUD 只写毛兑“本局 n 分，+m 金币”，不写净得。
- 控制：倾斜为主（加速度计），手指拖为备用；长按场地（手指基本不动、0.5 秒）暂停。无顶部暂停钮（2026-11-01 已删，见蛇/地鼠）。

## 加速度计（官方模块）

驱动是 ESP Component Registry 的 `waveshare/qmi8658` **v2.0.2**（2026-11-06 实查：注册表 API 取 zip，对着 `include/qmi8658.h` 核对，API 没有凭记忆写）。用的接口：

- `qmi8658_init(&dev, bus, QMI8658_ADDRESS_HIGH)`（0x6B，与板子一致；init 内置 WHO_AM_I 校验 0x05、写 CTRL1 0x60、accel 8G/1000 Hz、gyro 512 dps/1000 Hz、使能 accel+gyro）
- `qmi8658_set_accel_range(2G)`、`qmi8658_set_accel_odr(125 Hz)`、`qmi8658_set_accel_unit_mps2(true)`、`qmi8658_enable_sensors(...)`、`qmi8658_read_accel(...)`
- 注意：头文件里声明的 `qmi8658_read_accel_mg()` / `qmi8658_read_accel_mps2()` 在 v2.0.2 的 `qmi8658.c` 里**没有实现**（只是声明），直接调用会在链接期报 undefined reference。单位是 `qmi8658_dev_t` 上的一个标志位，改成 init 时 `qmi8658_set_accel_unit_mps2(&dev, true)`、读时 `qmi8658_read_accel()`。

只用加速度计（重力方向直接算倾角、不漂移），陀螺仪不开（UI 里软件低通平滑已够，陀螺仪只加耗电）。只轮询（每 tick 一次），不用中断引擎（1.4 教训：电池下不可靠）。功耗：init 后立刻 `DISABLE_ALL` 睡眠，游戏页打开才 `wake()`、离开就 `sleep()`，传感器在游戏外不耗电。

倾斜映射（`muse_goldrain_ui.c` 顶部四个旋钮）：增益 40 px/(m/s²)（约 35° 倾斜 ≈ 5.6 m/s² 可移满 240 px 场地）、死区 ±0.5 m/s²（约 ±3°，手持不漂移）、低通 0.35、符号 +1。**轴向与符号须实机标定**：芯片贴装方向决定哪根轴是左右、哪个符号是右，见验收清单；跑反了只改 `MUSE_GOLDRAIN_TILT_SIGN` 为 -1。

## 手感定稿（2026-11-06，实机试玩后，随 1.5.1 发布）

用户的四条反馈与落地方式：

1. **左右反了**：`MUSE_GOLDRAIN_TILT_SIGN` 1.0 → **-1.0**（左低右高现在向左）。芯片贴装方向决定符号，这一处就是标定旋钮，改回去也只改这一处。
2. **对局中黑屏休眠**：`on_tick()` 在 PLAYING 里每个 tick 调 `muse_state_poke()`，空闲计时不被推进；开始 / 暂停 / 结束页不 poke，照常到点休眠。与视频播放（`muse_video.c`）、语音回合（`muse_voice.c`）是同一套做法。
3. **去掉脚下的长条板**：板子是精灵图自带的（53×66 里第 63–65 行的亮色像素 + 两端亮块），生成脚本不在本机，所以在 `muse_goldrain_sprite.c` 的像素数据上就地擦掉（保留鞋底那一列深色像素），文件头已注明「重新从原画生成会把板子带回来」。
4. **速度再慢**：金币下落 90/4/150 → **65/3/110**（起速 / 每秒增量 / 封顶）；倾斜移动原来是「一个 tick 直接跳到目标位置」，现在按 **130 px/s** 滑过去（240 px 约 1.8 s），手指拖动仍是 1:1。主机测试的期望值已同步。

## 验收清单（用户本机）

```sh
cd esp32
tools/muse/board.sh build lcd185b   # 看 check_sizes：app 须 < 4 MB
tools/muse/board.sh flash lcd185b
```

1. 互动 → 小游戏列表出现第 5 行“金币雨”，可竖滑；点进后标题“金币雨”、开始钮“开始”、提示“左右倾斜移动，长按中间暂停”。
2. 倾斜：板子向右倾，毛毛向右走；向左倾，向左走。**跑反了**：把 `muse_goldrain_ui.c` 的 `MUSE_GOLDRAIN_TILT_SIGN` 改 -1（只改这一处）。手持平放桌面时她应基本不动（死区）。
3. 拖动备用：手指在场地里拖动，她跟手指走；拖动中手指停住 0.5 秒**不应**暂停（只有基本不动的长按才暂停）。
4. 长按中间区域 0.5 秒 → “已暂停”+“继续”；返回箭头出现，点回小游戏列表；再进应从暂停态恢复（不重新扣费）。
5. 接金币 +1 分；接炸弹 **−5 分**（积分可变负数，HUD 会显示负分）；炸弹**不会**提前结束游戏，30 秒一定打满；炸弹掉出底边不扣分。
6. 30 秒到 → 标题变“游戏结束”，计分行变金“本局 n 分，+m 金币”；负分局应显示 +0 金币（不是负数）；“再来一局”钮带“- 5 金币”，点下再扣 5。
7. 金币 <5 时点开始 → 拒绝提示“金币不够（需 5 枚）”，不扣费、不开局。
8. 子页面不能右滑到对话页（禁滑），三个点不出现；按 BOOT 回对话页。
9. 串口看开机行：应有 `muse_imu: QMI8658 ready`；若无芯片/探不到，应只有一条 `QMI8658 probe failed` 警告，游戏仍能用拖动玩。
10. 打砖块未做：本分支只有金币雨；打砖块仍是待定项。
