# 喂食每日上限滚动修复（2026-11-07）

分支 `feat/feed-daily-roll-20261107`，只推分支、不合 main。

## Bug（用户 2026-11-07 报）

互动 → 喂食页面：不管 8 点之后还是 0 点之后都显示“今日已喂食”；点三种食物，米饭始终是“今天已经喂过”，蛋糕和咖啡正常。不是刷新时间的问题。

## 根因：每日上限只在喂食那一刻才滚动

喂食每天每种 +10，靠 `feed_mask` 三个 bit（米饭 bit0、蛋糕 bit1、咖啡 bit2）+ `feed_day` 记。清零的逻辑在 `roll_cap()`（`muse_pet_model.c`）：只有当天的 day 大于存着的 `feed_day` 时才把 mask 清 0。

但 `roll_cap` 只在喂食动作里才被调（`muse_pet_model_apply` 的喂食分支）。工作线程每 30 秒跑一次 tick（`MUSE_PET_TICK_MS 30000`），tick 里只算生活费（`muse_pet_model_decay`），根本没碰喂食上限。所以：

- 午夜一过，日子变了，但 `feed_mask` 还躺在昨天的状态（昨天三种都喂过就是 `0b111`），没人去清它。
- 快照（UI 读的那份）也就还是昨天的 `0b111`，直到第一次点喂食，模型才在那一刻清零。

于是：

1. 新一天，主页面喂饭那行读到 `feed_mask == 0b111`，显示“喂饭 ｜ 今日已领满”——读的是昨天的 mask。
2. 点米饭：`on_feed_food` 先记 `s_last_feed_before = (mask & bit0) ? 1 : 0`，快照还是昨天的，记成 1。
3. 模型结算：`roll_cap` 清零 mask、把 `feed_day` 改成今天，bit0 置位、**+10 金币**。米饭的币是给了的。
4. 反馈回来：`paid = (mask & bit0) = 1`，但文案条件是 `paid && !s_last_feed_before`，`s_last_feed_before` 是 stale 的 1，所以显示“喂了米饭（今天已经喂过）”。**币给了，话说错了。**
5. 再点蛋糕：快照已被米饭那次反馈刷新（mask `0b001`），`s_last_feed_before = 0`，显示“喂了蛋糕 +10 金币”。咖啡同理。

**不是米饭专属 bug**：每天第一次点的那个食物必然中招，因为只有它撞上了 stale 的快照。米饭排第一个，用户自然先点它。如果某天先点蛋糕，那天就是蛋糕报“已经喂过”。

**日界口径**：日界现在是本地午夜 0 点（2026-11-05 用户定，提交 `1d5fc2f`“喂饭日界改本地零点”，`MUSE_PET_DAY_OFFSET_SECONDS` 从 0 改为 `8*3600`），不是 8 点。无论哪种日界，mask 都是懒滚动，所以过了日界还是显示“已喂”，直到第一次喂食。

## 修复

模型加一个公开函数 `muse_pet_model_roll_daily()`（`muse_pet_model.h/.c`），对 `feed_day/feed_mask` 和 `touch_day/daily_touch_coins` 各做一次 `roll_cap`。工作线程在两处调它：

- 启动时初次结算后（`muse_pet.c`，`muse_pet_model_decay` 之后）：第一份快照就是新鲜的，哪怕板子在日界之后才开机。
- 每 30 秒的 tick 里（`muse_pet.c`，`muse_pet_model_decay` 之后）：午夜过后 30 秒内快照就刷新。

`roll_cap` 是幂等的（day 没变就不动），时钟未校准时什么都不做（守门保留），回滚时不往回走（不会重复发奖励）。运势不滚（它按需抽，`PET_FORTUNE` 分支里按 day 判断）；数独账本也不用滚（`muse_pet_sudoku_today()` 自己比对 `sudoku_day` 和今天）。摸摸的每日上限是同样的懒滚动，顺手一起滚了。

UI 不用改：快照新鲜了，主页面那行和第一次喂食的文案就都对了。

## 已验证（本机）

- 主机经济测试通过：`python3 -m unittest tests.test_pet_economy`（cc -std=c11 -O2 -Wall -Wextra -Werror，ASan+UBSan），新增用例覆盖：
  - 三种都喂满后 `roll_daily` 到新一天 → `feed_mask == 0`、`feed_day` 前进、币数不变（滚动只清零、不发币）；新一天喂米饭 +10（已扣生活费 20 后的净数），第二下不重复给。
  - 摸摸到顶后 `roll_daily` 到新一天 → `daily_touch_coins == 0`，再摸给币。
  - 同一天重复 `roll_daily` 无变化；时钟回拨不往回走、不重复发奖励；时钟未校准时什么都不做。
  - 顺手修正了 harness 里 `day_now` 的过期注释（`MUSE_PET_DAY_OFFSET_SECONDS` 是 `8*3600` 不是 0；3600 + 28800 = 32400 < 86400，仍落在当天内，数学没变）。
- **未做**：`idf.py build`（本机无 ESP-IDF 工具链）与实机测试。编译与刷机由用户在本机做，见验收清单。

1. 今天三种食物都喂过一次（金币 +30），等午夜过后（或改天早上）再看：主页面喂饭那行应显示“喂饭 ｜ 每种 +10金币”，**不是**“今日已领满”。
