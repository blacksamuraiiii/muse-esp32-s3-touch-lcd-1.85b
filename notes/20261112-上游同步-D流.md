## D1：按压门槛移植（上游 d0a65ab，已做）

600ms 按住 + 至少 500ms 按住期间录音才发，带预录环（开口词不丢）；300–600ms
提示 HOLD LONGER TO TALK。取代 1 秒录音下限（MIN_HELD_FRAMES，用户 2026-10-16 定）；
3 秒补丁已作废，不用。能量门是我们 fork 自己的加法（上游没有），移植时保留。

移植中发现并修了一个真问题：最初整段缓冲一次重放、门后才设，PSRAM 路径下 hold 音频
不计 voiced，mic 在准入后第一个 live 读就失败时会被判"not speech"。已改成先重放
pre-roll 部分测 room、设 gate，再重放 hold（门开着计 voiced）；低内存路径不动（hold
在循环里随读随排、门本来就开着）。PSRAM 与低内存两路行为对齐，host 测试场景 63 覆盖。

新 host 测试 `test_muse_ptt_admission`（准入 50–57、顺序 60–63、唤醒 70–74/78/79/82–84；
PSRAM/无 PSRAM/Passport 三档，48 个场景子项全过）。

## D3：电池可借项（上游 be49f02，已做）

`read_power` 改上游式（板文件 `board_waveshare_s3_touch_lcd_185b.c`）：

- 任何读失败清掉上次样本报未知 -1，永不报 0%、永不留旧值；样本每次都发布（永远返回
  ESP_OK），USB 独立于 gauge 照常更新。调用方 `muse_input.c` 的轮询不用改。
- 先查 BATTPRES（无电池即未知，不是 0%），再查 INITCOMP 且不在 CFGUPDATE，电压/电量/
  电流范围校验（soc >100 或 mv <2000 或 mv >5000 即非法）；电流按有符号读（组件
  `bq27220_get_avgcurrent` 本来就返回 int16_t）。
- 充电判定：`charging = (avgcurrent > 0) && !DSG`。旧的 `!DSG` 在弛豫时也判充电，错的。
  状态读失败不再猜方向（旧代码 `bs.full = 0`  fallback 实际判成"在充电"，注释还写反了）。
- 失败日志只记一次（同错重复不刷屏，错变了才再记）；双零特判（soc==0 && mv==0）删了，
  由 mv 范围校验覆盖；0%（soc=0、mv 正常）仍是合法值。
- `muse_battery_note_power` 加 unknown 守卫：pct<0 时不启停测量、不更新 pct_now/mv_now；
  仅 USB 被证实才停表（一次总线毛刺不终结一次多小时的测量）。充电电流 >0 计入测量启停
  （`battery = on_battery && !p.charging`），修 USB 检测盲区导致的续航计时误算。
- 残留盲区（未修）：电池已满、充电电流 ~0、又插着只充电适配器时，仍会误判为电池供电
  （无电流信号可分辨）。影响只是一次平坦的测量记录，不污染学习状态。
- 附带：`muse_ptest_board_service` 里 `ESP_RETURN_ON_ERROR(read_power(...))` 现在永不触发
  （read_power 恒回 ESP_OK），gauge 未知时 ADC_SAMPLE 采样记 0 mV——是"未知"的诚实记录，
  不是回归。

测试：新 `test_lcd185b_board.py`（抽取生产 read_power + round_area：逐像素对齐扫全屏、
决策表 10 组）与 `test_muse_battery.py` 扩展（未知读数 hold、未知+USB 停表、充电停表/
禁开局、弛豫不停表、学习周期只认真充电）。harness `p` 命令加可选 charging/ma 字段，
旧三字段调用不受影响；新增 `l` 命令看学习文本。

附带修了一个基线错误：`muse_battery.c` 的学习持久化用 `nvs_get_u8`/`nvs_set_u8`，harness
只有 u16 版，battery 测试在基线里一直是 setUpClass ERROR（2 个）。harness 与
battery_fakes/nvs.h 补上 u8 版后，battery 测试全过——基线错误数 10 → 8，失败 27 不变。

## 只评估、没合的

### 653312a：表情柔和 17 行（不采用为移植）

内容：说话时 gaze 缩放 0.3f→0.55f、MOUTH_TALK 高度钳制 `clampf(open,0,1)`→`clampf(open,0,.45f)`、
SPEAKING 的 mouth_open 缩放（有声 2/3、无声 1/2，上限 .45）+ 停顿超 ~0.52 秒时闭眼微笑
（EYES_HAPPY + MOUTH_GRIN）；另改 docs 与 test_speaking_animation.py。

结论：**不能直接移植**。我们渲染器是毛毛定制版 `esp32/avatar/muse_pixel.c`（583 行 v8），
上游是 1202 行默认像素头像；三处改动的代码（`tgx *=`、MOUTH_TALK、`mouth_open = speech.mouth`、
EYES_HAPPY）在我们文件里根本不存在。意图已由我们渲染器自身实现（说话嘴最高 3px、圆"o"形、
不张大嘴）。唯一无等价物的是"停顿闭眼微笑"，可作日后可选小改，需用户定。

### 16adad8：提示 5 秒过期（待定，不合）

内容：`muse_state_set_hint` + `MUSE_HINT_MS 5000`，过期在 `muse_state_caption()` 被 UI 轮询
时懒清理；普通 caption 取消待定过期；HOLD LONGER TO TALK / PHONE SETUP OFF / SPEAKER ON-OFF /
HOLD TO MUTE-UNMUTE 变 hint；其余 caption（回复、错误、状态）不变；新测试
test_muse_caption_hint.py（264 行）。

落点（我们树）：`muse_state.c/h`（set_caption 结构）、`muse_input.c` 的 toggle_phone_setup
与 aux_button（saved_hint 恢复）、`muse_ui.c` 的 on_speaker_event、`muse_voice.c` 的
`too_short()`。D1 已把 `too_short()` 先做成普通 caption 版（等价于现行两处
`go_idle("HOLD LONGER TO TALK")`），16adad8 批了再把 helper 体改成 `set_hint`。

### 463bd2a：token 保 Wi-Fi（待定，不合）

内容：401 终局（revoked）→ `VM_API_ERR_REVOKED`，`config_unpair()` 只清 pairing 保 Wi-Fi；
403/5xx/网络失败保 token 并退避（独立的 `s_last_vm_auth_refusal_us` 戳）；显式 unpair 与
setup 失败清理也保 Wi-Fi；5 秒 hold 与"Reset pairing"仍是整机恢复、忘 Wi-Fi。量级：
app.c +229、config_store、vm_api、新 783 行 harness + 合同测试。

我们树现状：没有 `config_unpair` / `VM_API_ERR_REVOKED`；但已有自己的本地 401 处理
（app.c 注释："A 401 from fetch_vms no longer unpairs the device"；
`note_vm_credentials_refused()` 退避；`ensure_access_token_ready_with_gate_held()` 的
`allow_stale_on_refresh_failure`）；显式 unpair（BLE unpair / device.unpair）仍走
`config_clear_setup()`、忘 Wi-Fi。评估：我们本地机制已覆盖标题情形（401 不 unpair），
剩余差值是 403/5xx 退避分离与显式 unpair 保 Wi-Fi；移植等于换掉本地机制，量大且行为
关键，需单独评审——D 流内不合。
