## 3. P1 — 合入前需处理

### P1-2 【本次引入】生成脚本失败会留下"未 pin 行高"的脏字库

- **问题描述**：脚本先 `sed … > "$OUT"` 落盘，再用 python 正则把 `    .line_height = 31, / .base_line = 9,` 替换为 20/5，`assert n == 1` 依赖精确输出格式与固定指标。任一条件不满足（上游 Noto 更新、lv_font_conv 输出格式变化、行高不再是 31/9）即 `set -e` 退出，但 `$OUT` 已是**未 pin 的完整字体文件**，极易被误提交。README 明确 31/9 会把 caption band 撑到 72 px、把 Muse 顶进 READY 标签。桌面产物里的 "Fork pin" 注释证明本次 pin 确实执行成功。
- **影响范围**：字库再生成流程；一旦误提交就是全屏布局回归。
- **分级依据**：破坏性静默失败，且触发条件不受控 —— `curl` 拉 `noto-cjk/raw/main/...NotoSansSC-Medium.otf`（**未 pin tag/commit、无 checksum**），`npx -y lv_font_conv@1.5.3` 每次联网解析，产物不可复现。
- **关联位置**：`gen_cjk_noto_font.sh:29-30, 43-62`；`fonts/README.md:36-40`。
- **处理方向**：先写临时文件、pin 成功后再原子 `mv` 到 `$OUT`；pin 按字段名独立替换并校验替换后的值，不硬编码 31/9；字体 URL 固定 commit/tag + sha256；生成后自动 diff 校验（`Opts` / `cmaps` / 行高 / 体积）。
- **待确认**：上游 Noto 版本变动是否会影响 line metrics（未实测）。
