## 一、总体结论

1. **代码质量稳中有升**：1.5.3c 的 3 条 Blocker 与 1.5.4b 评审项（F-A1 闹钟同日重响、WithCaps 删除配对、唤醒幻触宽限）均已核实落地；label 同值短路已从 menu 推广到全部游戏页；机械网（atoi / 无界 sprintf / 任务创建-删除配对 / timer pause-resume 配对）零命中。新合入的 linkrecovery（半开检测、DMA stall、outage 历史）与闹钟全链路（RTC 触发、F-A1 同日戳、once 自关）实测逻辑严密，未发现崩溃级缺陷。
2. **但固件容量已到红线**：4M app 槽仅剩 **61,440 B（1.5%）**，且 1.5.4c 宣称「合入体积精简约省 185KB」中约 **177 KB 的字库部分实际没有落地**（详见 P0-1）。再合任何带体积的功能（唤醒词 +148 KB、任何新页面）都会溢出分区。
3. **流畅度有两个具体抓手**：描红页每触摸点全量重算判分覆盖（P1-2，书写末段单事件最高约 16 万次距离计算）；frame_ms=40 的主帧率有下调到 33ms 的空间但须实测（P2-5）。

## 三、缺陷清单（P0–P2）

### P0（容量红线，账实不符）

**P0-1 CJK 字库精简未合入主线，app 槽余量仅 61,440 B。**
- 实证链：① 当前 `components/muse/fonts/muse_font_cjk_noto_16.c`（6.1M）文件头 Opts 行仍是旧参数——`--no-compress`、`-r 0x3000-0x30FF`（含假名）、无 `--no-kerning`、手写码位清单；② 该文件最后一次改动是 `468fc0b3`（1.5.3c 补「筊」），2c214d8 与 1.5.4c 合并 `76273c2` 的 stat 里都没有它；③ 11-21 构建的 map 实测 `.rodata.glyph_bitmap` 855.2 KiB（未压缩明文）、`.rodata.kern_pair_glyph_ids` 16.2 KiB、kern values ~4.6 KiB——三项均应已删；④ `notes/20261120-CJK字库再生说明.md` 写明原因：新文件 5.5 MB，GitHub push-files 接口 413 推不上去，精简被挂起。
- 后果：1.5.4c 的「约省 185KB」实际只兑现了美术部分；唤醒词（上游实测 +148 KB）的装填前提不存在；下一版任何新增都可能溢出 4M 槽（bin 4,132,864 / 槽 4,194,304）。
- 修法（文档齐全，直接执行）：本地跑已合入主线的 `esp32/tools/muse/gen_cjk_noto_font.sh` 生成新字库（预期省 ~177 KB），**本地 git 提交推送**（不要走 push-files，413）。字库文件每次整体重写，禁止手改 `.c`；生成后按说明 §6 验证（7,242 字形、glyph_bitmap 721,254 项、无 kerning、压缩标志在）+ 实机全文渲染回归。风险：假名若出现会豆腐（可接受，界面无假名）；拉丁间距略松（预期内）。

### P1（功能错误 / 显著性能）

**P1-1 PET_FEE 回执按可见页路由，六游戏共享同一 action，跨页竞态未修且窗口扩大。**
- 位置：`muse_interact_ui.c:1257-1295`（POOR 与 STORAGE 两条链，注释自称"route by the visible page"）。
- 机制：snake / whackamole / goldrain / doodle / breakout / tictactoe 六页共用 `PET_FEE`，回执本身不带来源。worker 回执队列 8 深、命令 worker 30s tick——A 页开局的费用回执积压后，用户已切到 B 页时按 `s_page` 路由：B 页被误重置（breakout 的 fee_refused 只在 PLAYING/PAUSED 动作，见 `muse_breakout_ui.c:785-798`，但 B 页此刻往往正是刚开局）；A 页真正需要的那份永远收不到，费用实际未扣而游戏照跑。
- 触发前提：回执积压 + 快速跨页切换（现实操作完全可达，尤其儿童连点）。
- 修法（二选一）：① `muse_pet_feedback_t` 增加来源 tag（request 侧带、worker 侧回填），路由按 tag；② 每个 UI 页记录自己的「在途费用请求」标志，回执广播到六页、由各页自判（改动面更小，不用动 worker）。host 侧可仿 pet_economy_harness 加一条「A 页请求、B 页可见时回执到达」的用例。

**P1-2 描红每个触摸点全量重算覆盖度，书写后期单事件约 7–13 ms，是「写字末段变卡」的第一嫌疑。**
- 位置：`muse_tracing.c:311`（add_point 末尾每点调 refresh_coverage）× `:180-218`（全量 O(点数×样本数) 重算）。
- 量级（代码可算）：点数 ≤512、样本 ≤320；写到第 400 点时每事件 400×320≈12.8 万次 dist2，240 MHz 下含访存约 7–13 ms。触摸事件 30 ms 周期上吃掉 1/4–1/2，加上同帧 ink 线段重绘，书写后期掉帧可感。注释「recomputing on each point is cheaper than incremental state」论证不成立：覆盖单调（点只增），增量只需对新点标一次 O(样本)=320 次。
- 修法：`refresh_coverage` 改增量——新点只把「此前未覆盖的样本」置为覆盖（O(样本)），score/stroke_cover 随之累加；stray 已是增量不动。reset/set_char 时一次全量重建基线。host harness（若有）可断言增量与全量结果逐字符等价后再换。

### P2（精简 / 体验 / 预防，按收益排序）

**P2-1 montserrat 四字号全字符集编入，合计 48.3 KiB，使用面其实极窄。**
- map 实测：montserrat_28 31.7 KiB、montserrat_20 16.6 KiB、16/14 约 8–10 KiB 级。
- 用途核对（grep 全仓）：28 只用于闹钟滚轮选中行数字+冒号（`muse_alarm_ui.c:138,179`）、数学等式行（`muse_mathpractice_ui.c:551,566`）、quiz 扬声器符号、配对码；16 只用于状态栏时钟/电量数字（`muse_ui.c:101-102`）；14/20 含 LV_SYMBOL 与少量英文。
- 修法：仿 `muse_font_clock_48` 的先例（48px 只裁数字+冒号，~4.8 KiB），对 28/16 重生成「数字 + 冒号 + 所用 LV_SYMBOL + 大写字母」子集，预计省 30–40 KiB。代价：改用字体的字符清单，需一次性核对（漏字=豆腐），建议与 P0-1 同批做、一次回归。

**P2-2 词卡 / 主网格 / 学习页 art 共 34 张 ARGB8888 各 16 KiB（map 逐张实证，合计 ~544 KiB）。**
- `muse_wordcards_art_*` 23 张 + `muse_main_grid_art_*` 4 张 + `muse_learn_art_*` 4 张 + `muse_interact_hand_*` 3 张，均 64×64×4。
- 仓库已有成熟先例：主网格图标本身就是 A8 + 运行时 recolor（`muse_interact_ui.c:656-663`）、拼音位图同法（`muse_tracing_ui.c:427-431`）。同法改 A8 每张 16→4 KiB，全套省约 **400 KiB**，观感=单色版画风（是否接受需拍板，见 §九决策点）；或走 memopt F1 的 RLE 方案（保彩色，估算词卡部分省 ~187 KiB，须实测解码耗时）。

**P2-3 转盘盘面 112.5 KiB RGB565 无压缩。** `muse_luckywheel_art_wheel.c`（240×240×2）。12 格纯色扇区 + 中心圆，RLE 后预计 ~50–60 KiB。与 P2-2 同属 F1 路线，一次定解码路径两处受益。

**P2-4 描红静态缓冲留在内部 DRAM：s_pool 4.0 KiB + s_trace 3.6 KiB（map `.bss.s_pool/.bss.s_trace` 实证）。** 访问频率为每触摸事件数十字节，PSRAM 可承受。加 `EXT_RAM_BSS_ATTR` 省 7.6 KiB 内部 RAM，一行改动 ×2 文件（`muse_tracing_ui.c` 静态池、`muse_tracing.c` 若 s_trace 在此文件则改其定义处——以实际定义为准）。

**P2-5 主帧率 frame_ms=40（25fps）有上调空间，但必须实测。** `board_...185b.c:2555`。全帧 QSPI 传输账：360×360×2 B ≈ 259 KB / 80 Mbps ≈ 26 ms < 40 ms，bands 流水下 33 ms（30fps）理论有余量。改一行可试，**验收看连滑撕裂与心跳 ui=frames**（不可只看编译通过）。

**P2-6 描红「停笔 2 秒即判」对慢写儿童偏急。** `muse_tracing_ui.c:308-318`：TRACING 且 2 s 无触摸即 grade；`muse_tracing.c:244` PASS_PCT=50 即 DONE 弹「再写一次」卡。孩子分笔慢写、中途停顿思考（>2 s）会提前收判定卡，打断书写节奏。这是 1.5.4d 用户反馈后刚调的口径（判分两档），当前行为是「设计如此」——**不改代码，提请确认**：是否将 settle 提到 3–4 s，或改成「RELEASED 后 2 s」而不是「任意事件后 2 s」。

**P2-7 快照失败时描红列表页显示「金币 0/100」误导。** `muse_tracing_ui.c:449-458`：have=false 时按 0 渲染；词卡页同场景的先例是显示「--」（`muse_interact_ui.c:604`）。一行对齐。

**P2-8 打砖块 re-serve 分支当前不可达，恢复多命前须补测试。** `muse_breakout.h:101` LIVES=1，`muse_breakout.c:299-303` 注释如实声明：恢复 3 条命时该分支复活且无 host 覆盖，且 re-serve 无玩家准备窗口（球即刻飞出）。记档备忘，不改。

**P2-9 上游新增未合项（esp32 相关，见 §四）。** 维持「每正式版合并一次」的节奏即可，其中 Wi-Fi rejoin 与 BodyChunks 两条优先。

## 七、运行 / 触摸流畅度专项（用户重点）
