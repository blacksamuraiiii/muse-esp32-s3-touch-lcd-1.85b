## 0. 需求（2026-10-21 二次定版）

用户对第一版的三条澄清，**推翻了原文档的「pitch 变化 55°」硬判据**：

1. **亮屏不要太灵敏**，但也不是必须抬腕到某个角度。
   真正要挡的是两个场景：
   - 桌面轻碰、手扫过 → 不亮
   - **放进包里，晃动一路触发亮屏** → 要自己安静下来
   拿起并看向屏幕 → 应该亮。
2. **翻面深睡保留**（屏黑、按键/触摸全吞、只有翻回来解除），
   但**必须有长按 8 秒强制退出 park 的逃逸**——防止基准学错导致永久锁死。
3. **不是必须抬腕才能说话，而是必须「屏幕已经亮着」才能长按说话**。
   屏黑时的长按只负责亮屏，不能同时开始录音。

**结论：不换组件、不引入 25Hz 轮询。** 只做四处增量改动（§5 清单）。

为什么不用 `waveshare/qmi8658` v2.0.2（上一版评审的结论，此处留档）：

- `qmi8658_enable_wake_on_motion()` 只写 `0x0B`/`0x0C`，**不发 CTRL9 = 0x08**，WOM 参数不生效；
- `qmi8658_init()` 写 `CTRL1 = 0x60`，**不含 bit3 INT1_EN**，GPIO8 永不输出；
- `qmi8658_read_accel_mg()` 只有声明、**没有实现**，调用即链接失败；
- 组件的 I2C 读写没有 `ESP_PM_NO_LIGHT_SLEEP` 锁，自动 light sleep 会截断帧；
- `qmi8658_init()` 自己 `i2c_master_bus_add_device(0x6B)`，与板级 `s_imu` 重复。

## 2. 亮屏判定：三层漏斗

原文档的「25Hz 采样 + 16 样本环 + 400~700ms 基准 + dp>55°」有三个问题：
功耗与 light sleep 冲突、16×40ms=640ms 取不到 700ms、pitch 依赖未标定的轴向。
换成下面这条**事件驱动**的三层漏斗，采样由硬件 WoM 中断触发，待机功耗不变。

```
[0] WoM 硬件门   QMI8658 加速度突变 > CONFIG_MUSE_IMU_WAKE_MG(200mg) → 拉 INT1
                        ↓ 唤醒 light sleep
[1] 姿态门       等 400ms 让手停稳 → 读一次重力矢量
                 与「息屏那一刻的姿态」夹角 ≥ 30° 且 |g| ∈ [0.75, 1.25] g
                        ↓ 通过才亮
[2] 误触发回收   亮屏后 6s 内没有任何触摸/按键 → 自己熄屏，误触发计数 +1
                 连续 3 次 → 进入抑制模式：角度门提到 55°、回收缩到 2.5s
                 任何一次真实交互 → 计数清零、退出抑制
```

三层各自挡一类误触发：

- 层 0 挡桌面振动（阈值已有，保持 200mg）；
- 层 1 挡「拿起来但没看」（平端着走，夹角≈0）；
- 层 2 挡包里：包里翻滚能过层 0 和层 1（姿态变化大），但**没人交互**，
  所以 6s 后自己灭，连续三次后门槛抬高，包里越放越安静。

层 1 用**重力矢量夹角**而不是 pitch：不依赖 QMI8658 在 PCB 上的旋转方向，
不需要标定轴向，任意方向拿起看屏幕都算，符合「不用那么严格」。
30° 比原文档的 55° 松，但它是全向的，实际挡掉的误触发更多。

### 2.1 `muse_imu.h` 追加声明

```c
/* Remembers which way gravity pointed when the screen went dark. The wake
 * check below is measured against this, so "did the device change posture"
 * needs no assumption about how the part is rotated on the PCB.
 * Ignored (and the previous reference kept) when the device is still moving:
 * a reference taken mid-swing describes nothing. */
void muse_imu_note_sleep_posture(void);

/* True when gravity has turned by at least `min_deg` since that reference and
 * the device is at rest now - "it was lifted and turned towards a face", not
 * "it wobbled". Returns true when no reference exists: a missing baseline must
 * light the screen, not lock the user out. */
bool muse_imu_wake_is_deliberate(int min_deg);

/* Degrees between the current gravity vector and the sleep reference; -1 when
 * either is unknown. For the log line and the console. */
int muse_imu_posture_delta_deg(void);
```

### 2.2 `muse_imu.c` 追加实现

放在 `muse_imu_face_down()` 之后（`s_up_mg` / `accel_mg()` / `vec_mag()` 都已在其上方定义）。

```c
/* ------------------------------------------------------- wake posture */

/* Gravity when the screen went dark, in mg. Not the same thing as s_up_mg:
 * that one is "which way was up when the device booted", this one is "which
 * way was it pointing when the user put it down", which is the posture a lift
 * has to change away from. */
static int s_sleep_mg[3];
static bool s_sleep_known;

/* A reading may only decide anything near rest: mid-swing the vector points
 * everywhere on the way round, and so does the angle against the reference. */
#define WAKE_STILL_MIN_MG 750
#define WAKE_STILL_MAX_MG 1250

static int angle_deg_between(const int a[3], const int b[3])
{
    const float dot = (float)a[0] * b[0] + (float)a[1] * b[1] + (float)a[2] * b[2];
    const float ma = sqrtf((float)a[0] * a[0] + (float)a[1] * a[1] + (float)a[2] * a[2]);
    const float mb = sqrtf((float)b[0] * b[0] + (float)b[1] * b[1] + (float)b[2] * b[2]);
    if (ma < 1.0f || mb < 1.0f) {
        return -1;
    }
    float c = dot / (ma * mb);
    if (c > 1.0f) c = 1.0f;
    if (c < -1.0f) c = -1.0f;
    return (int)(acosf(c) * 57.29578f);
}

void muse_imu_note_sleep_posture(void)
{
    int g[3];
    if (!accel_mg(g)) {
        return;   /* bus error: keep the old reference, it is still the last good one */
    }
    const int mag = vec_mag(g);
    if (mag < WAKE_STILL_MIN_MG || mag > WAKE_STILL_MAX_MG) {
        /* Put down while still being carried: this vector is a snapshot of a
         * swing, not a posture. Keep what we had. */
        ESP_LOGD(TAG, "sleep posture not updated: %d mg is not at rest", mag);
        return;
    }
    s_sleep_mg[0] = g[0];
    s_sleep_mg[1] = g[1];
    s_sleep_mg[2] = g[2];
    s_sleep_known = true;
    ESP_LOGI(TAG, "sleep posture %d/%d/%d mg (%d mg)", g[0], g[1], g[2], mag);
}

int muse_imu_posture_delta_deg(void)
{
    int g[3];
    if (!accel_mg(g)) {
        return -1;
    }
    if (s_sleep_known) {
        return angle_deg_between(g, s_sleep_mg);
    }
    if (s_up_known) {
        return angle_deg_between(g, s_up_mg);
    }
    return -1;
}

bool muse_imu_wake_is_deliberate(int min_deg)
{
    int g[3];
    if (!accel_mg(g)) {
        return true;    /* unreadable: let the user see the screen */
    }
    const int mag = vec_mag(g);
    if (mag < WAKE_STILL_MIN_MG || mag > WAKE_STILL_MAX_MG) {
        return false;   /* still in motion: wait for the next event, do not wake */
    }
    const int deg = s_sleep_known ? angle_deg_between(g, s_sleep_mg)
                   : s_up_known  ? angle_deg_between(g, s_up_mg)
                                 : -1;
    if (deg < 0) {
        return true;    /* no reference at all: never lock the screen out */
    }
    ESP_LOGD(TAG, "posture %d deg (%d mg), need %d", deg, mag, min_deg);
    return deg >= min_deg;
}
```

 * decides. Long enough for the hand to stop, short enough that the screen
 * still feels like it answered. */
#define WAKE_CONFIRM_MS 400
#define WAKE_ANGLE_SUPPRESSED_DEG 55
/* A screen lit by a lift that nobody touches is a screen lit for nothing -
 * which is the whole cost of carrying the gadget in a bag. After this long
 * without an interaction it goes back to sleep and counts as a false wake. */
#define WAKE_IDLE_RECHECK_MS 6000
#define WAKE_IDLE_RECHECK_SUPPRESSED_MS 2500
#define FALSE_WAKE_LIMIT 3

static bool s_wake_pending;
static int64_t s_wake_check_ms;
static int64_t s_wake_hold_ms;      /* when the lift was accepted, 0 = none */
static bool s_wake_interacted;      /* a touch or a button since then */
static bool s_wake_suppressed;      /* three idle wakes in a row */
static int s_false_wakes;
static uint32_t s_stat_ignored;     /* motion events the posture gate dropped */

## 3. 翻面深睡（行为定稿）

| 事件 | 行为 |
|---|---|
| 屏朝下且静止 ≥ 3 次读数 | `park(true)` → 屏黑、触摸全吞、按键全吞、正在录的音丢弃 |
| 屏朝下时长按 BOOT 8 s | `muse_imu_face_calibrate()` + `park(false)`，屏亮，重新学基准 |
| 翻回正面 | `park(false)`，屏亮 |
| 屏朝下时的其他按键 | 无反应（含 1.5 s 长按，不再关机） |

不需要陀螺仪。翻面是**静态姿态**判定，`muse_imu_face_down()` 现有的
`dot ≤ -700 mg` + 连续 3 次 + 静止窗口（0.6~1.4 g）已经足够；
开 gyro 只会增加功耗，原文档「加速度+陀螺仪配合」的说法不成立。

>    为 DEFINED / default 30 / range 15~90；
> 3. **完整链接没做**。本机直接 `ninja` 时 CMake 重配置被工程自己的
>    `cmake/validate_config.cmake` 拦住：
>    `ESP32 Device SDK requires cJSON nesting limit 16. Generated sdkconfig values
>    override newer defaults; regenerate the active isolated profile configuration.`
>    ——这是构建目录里的 `sdkconfig` 比 `sdkconfig.defaults` 旧导致的，与本次改动无关，
>    也不该由脚本去重置（会冲掉 `devices/sdkconfig.local` 的本机 overlay）。
>
> **下一步（需要你在正常的 ESP-IDF 终端里做）**：按 README 方式 B 跑一次
> `idf.py -B build-muse-waveshare-s3-touch-lcd-185b ... build`，确认
> `build-.../sdkconfig` 里出现 `CONFIG_MUSE_IMU_WAKE_ANGLE_DEG=30`，
> 然后按 §6.3 的九步实测。

## 6. 验收口径

### 6.1 应该出现的日志（`idf.py monitor`）

```
I (1234) muse.imu: sleep posture -120/30/980 mg (988 mg)     ← 息屏时记下基准
I (5678) muse_input: lift accepted (41 deg, need 30)          ← 拿起并转向
I (5690) muse_input: waking (lifted)
I (9012) muse_input: lift ignored (8 deg, need 30)            ← 平端着走
I (3456) muse_input: no interaction in 6000 ms: back to sleep (#1)   ← 包里
W (9999) muse_input: lift-to-wake suppressed: 3 idle wakes in a row, now needs 55 deg and 2500 ms
I (1111) muse_input: lift-to-wake back to 30 deg: the user is here     ← 真实交互
I (2222) muse_input: face down: parked (imu)
I (3333) muse_input: face up: unparked (8 s hold)
```

### 6.2 应该消失的日志

- 屏黑时按触摸不再出现 `PTT down (waking)`；
- 包里不再出现每分钟多次的 `waking (pickup)`。

### 6.3 实测步骤

1. 桌面轻碰外壳 → 不亮，日志 `lift ignored`。
2. 平端拿起、屏幕仍朝上 → 不亮。
3. 拿起转向脸 → 亮，`lift accepted`。
4. 放进包里摇晃 60 s → 最多亮 3 次，每次 6 s 内自灭，之后不再亮。
5. 从包里拿出、转向脸 → 亮（抑制在 4 之后已被真实交互复位？注意：
   拿出后第一次仍受 55° 限制，看日志是否 `lift accepted (58 deg, need 55)`；
   若偏紧，把 `WAKE_ANGLE_SUPPRESSED_DEG` 降到 45）。
6. 翻面 → `face down: parked`；屏全黑、触摸无反应。
7. park 下长按 BOOT 8 s → `face up: unparked (8 s hold)`，屏亮。
8. 屏黑时长按屏幕 2 s → 只亮屏，不录音；松手后再长按 → 开始录音。
9. 待机功耗：`>ptest.arm={...}` 跑 20 分钟，与改动前对比，
   平均电流差异应 < 5%（本方案不增加任何周期性唤醒）。

## 7. 风险与取舍

- **`s_wake_interacted` 的挂点**：最省事的做法是在每轮轮询里看 `ev`，
  但 `ev` 只在按键分支可见。若挂不上，退化为在三个按键处理函数入口各置一次，
  代价是「只按键不说话」也算交互——语义上没问题。
- **抑制模式的副作用**：连续三次误触发后，正常抬腕也可能要 55° 才亮。
  只要用户按一次键就复位，实测若觉得恢复太慢，把 `FALSE_WAKE_LIMIT` 提到 5。
- **park 下不再能直接关机**：这是 8 s 逃逸的代价。若用户更在意关机，
  可改成「park 下长按 1.5 s 关机、长按 8 s 退出 park」，
  但两个手势共用同一按键时，先到 1.5 s 的会吞掉 8 s，不可行。
- **姿态基准在「边移动边熄屏」时不会更新**：日志会打
  `sleep posture not updated`，此时沿用上一次基准。极端情况下基准是旧的，
  抬腕角度算出来偏大 → 更容易亮，方向是安全的。
