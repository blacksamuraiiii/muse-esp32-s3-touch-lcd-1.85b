## 0. 结论先行

1. **官方清单里有一块几乎同源的板：`Waveshare ESP32-S3-Touch-LCD-1.85C`。** 它和 1.85B 用同一颗 ST77916、同一套 QSPI 四线引脚（`SCLK40 / D0=46 / D1=45 / D2=42 / D3=41 / CS21`）、同一套 I2C（`SCL10 / SDA11 / INT4`）、同一套 I2S（`MCLK2 / BCLK48 / WS38 / DOUT47 / DIN39`）、同一对 codec（ES8311 + ES7210）、同样 360×360 圆屏。**差别只在：复位走 TCA9554、功放使能是 GPIO15、电量走 ADC 分压、没有 IMU/RTC。**【已确认】

2. **它的面板初始化表 = 我们的 `s_init_version_2`，只少一条 `{0x35,0x00}`（TEON）。** 归一化后 184 条逐字节相同，唯一差异是我们多了 TE 使能那一行 —— 而我们 `tear_avoid_mode` 是 `NONE`、也没定义 TE 引脚。**【已确认】**（见 §3.2）

3. **音频参数官方内部就有两套写法，我们抄的是另一块板，但两者等价：** 我们跟 `board_vn_s3_183.c`（`I2S_NUM_0` + `use_mclk=true` + `hw_gain{5.0,3.3}`），1.85C 用 `I2S_NUM_1` + `use_mclk=false` + 不设 hw_gain。逐项核过：**I2S 端口在 S3 上等价；`use_mclk=true` 匹配本板 MCLK 已布线到 GPIO2；`hw_gain{5.0,3.3}` 就是库默认值**（`esp_codec_dev_vol.c:54-59`，`pa_voltage==0` 时回落 5.0），所以 1.85C 的零值结构体和我们显式写的这份产生**同一条音量曲线**。→ **不是缺陷，不需要改通路**。**【已确认】**

4. **官方 34 块板里，`muse_imu.c` / `muse_rtc.c` 一个都没有**（上游只有 `muse_battery.c` / `muse_pmu.c`）。这两块是我们独有的能力，也是回上游 PR 的最大加分项。**【已确认】**

5. **我们要进官方清单，代码侧其实已经齐了**（Kconfig / CMakeLists / idf_component.yml / board.sh 四处都已有 `185b` 分支），差的是一个按 `devices/AGENTS.md` 走完验证清单的 PR。**【已确认】**（见 §7）

## 3. 头号参照：1.85C 逐项对照

### 3.1 硬件对照

| 维度 | 1.85C（官方） | 1.85B（我们） | 结论 |
|---|---|---|---|
| 屏 | ST77916 QSPI 360×360 | 同 | 同 |
| QSPI 引脚 | SCLK40 / D0=46 / D1=45 / D2=42 / D3=41 / CS21 | **完全一致** | 同 |
| 背光 | GPIO5，LEDC 20 kHz / 10 bit | 同 | 同 |
| 触摸 | CST816S `0x15`，SCL10/SDA11/INT4 | 同 | 同 |
| LCD 复位 | **TCA9554 `0x20` EXIO2** | **GPIO3 直连** | 分叉 |
| 触摸复位 | **TCA9554 EXIO1** | **GPIO1 直连** | 分叉 |
| I2S | MCLK2 / BCLK48 / WS38 / DOUT47 / DIN39 | **完全一致** | 同 |
| 功放使能 | **GPIO15** | **GPIO9** | 分叉 |
| 电量 | ADC1_CH7（GPIO8）200K/100K 分压 | BQ27220 `0x55` | 分叉 |
| IMU / RTC | 无 | QMI8658 `0x6B`（INT1=GPIO8）/ PCF85063 `0x51` | 我们多 |
| 分带 | `DRAW_BUF_LINES 72`（5 带） | `360/4 = 90`（4 带） | 参数差异 |

> 引脚级重合度：**QSPI 6 根 + I2C 3 根 + I2S 5 根 + 背光 1 根 = 15 根全部相同**。这在 34 块板里是唯一一块。

### 3.2 初始化表比对（关键证据）

归一化空格后逐行 diff：

```
条目数：1.85C = 184，我们 v2 = 185，我们 v1 = 182
1.85C vs v2 唯一差异：
  @@ 第 181 行 @@
    {0xF0,(uint8_t[]){0x00},1,0},
  + {0x35,(uint8_t[]){0x00},1,0},   ← 我们多这一条
    {0x21,(uint8_t[]){0x00},1,0},
```

`0x35` 是 **TEON**（Tearing Effect Line ON，参数 `0x00` = 只在 V-blank 时拉 TE）。我们 `tear_avoid_mode = ESP_LV_ADAPTER_TEAR_AVOID_MODE_NONE`，也没有定义 TE 引脚，**这条命令在当前配置下是无效果的空转**。1.85C 同样不发给它（虽然定义了 `LCD_TE = GPIO18`，但 `tear_avoid = NONE`）。

**它为什么在那儿**（2026-10-21 追溯）：

- **位置是对的**。两张表的尾部都是同一串 Sitronix 固定收尾：
  `F3/01`（接口控制）→ `F0/00`（退出命令集第 2 页，回到普通页）→ `35/00`（TEON）→ `21/00`（INVON）→ `11`（SLPOUT，延时 120 ms）→ `29`（DISPON）。
  TEON 必须在 DISPON **之前**发，让 TE 信号从第一帧就有效——顺序没有任何问题，只是这里没人收。
- **来历**：由 `ca38241`（2026-10-16「真机调试：修复屏幕、预置网络、接入语音播报」）引入，该提交的说明原文是「搬入微雪官方 BSP 的两张表并复刻其流程」——整表照抄，不是逐条筛选后写进去的。
- **旁证**：全仓库只有 3 处 `{0x35, 0x00}`——我们的 v1（`:323`）、v2（`:511`），以及 `board_vn_s3_183.c:117`。后者是 NV3023 控制器、284×240 方屏，与 ST77916 完全不同的芯片，却带着结构几乎相同的初始化序列（`E0-E8 / EC / F1 / F6 / FD / 3A / 35 / 36 / 21 / 11 / 29`）。`0x35` 是 ST7789/ST7796/ST77916/ILI9341 一整族共用的命令号，厂商 BSP 模板之间互相抄，它就这么留下来了。
- **官方两张表都没有它**：`board_waveshare_s3_185c.c` 的 184 条表（上游 PR #112）零出现；`esp_lcd_st77916` 2.0.2 内置表也零出现（那里的 `0x35` 都只是 `0xE0` 伽马参数和 `0xDD/0xDE` 的数据字节）。

**结论**：**保留**。删掉唯一收益是 v2 与官方表逐字节相同，而它落在已经验证过的出货路径上，属于"没有收益的回归风险"。已在其上方补注释说明它是空转的 TEON。

**结论**：我们的 v2 表就是官方验证过的那张表（厂商 BSP / xiaozhi 同源），v1 是另一块面板修订版的表。**【已确认】**

> **顺带记一笔**：GPIO18 在 1.85B 上是空闲的（引脚表只用到 0/1/2/3/4/5/9/10/11/21/38/39/40/41/42/45/46/47/48）。1.85C 把 TE 接在 GPIO18 上，1.85B 同门设计**很可能**也引出，但**未查证原理图**。若将来真要做防撕裂（`tear_avoid_mode` 改 `TE`），第一步是拿万用表确认 GPIO18 到面板 TE 焊盘是否通，而不是直接改代码。

## 4. 二号参照：另外四块

### 4.1 OSTB EchoEar-2ST —— 第三张 ST77916 初始化表

`board_ostb_echoear_2st.c`：`LCD_SCLK 8 / MOSI 4 / CS 3 / RST 9 / BL 41`，**4 线 SPI 而非 QSPI**，`DRAW_BUF_LINES 10`。屏同为 ST77916 360×360。

价值：**面板花屏时的第三份对照表**（`boards/ostb_echoear_display_init.h`）。当 v1/v2 都不对时，这是排查「是不是面板批次又变了」的第三票。**【已确认】**（同芯片、不同总线，不能整段照抄）

### 4.2 VN S3 183 —— 我们音频的真正母本

`board_vn_s3_183.c:audio_init()`：`I2S_NUM_0`、`use_mclk = true`、`hw_gain = {5.0, 3.3}`、`mic_selected = MIC1|MIC2`、`mic_slot = 0`（slot 1 是喇叭参考）。

我们的 `board_waveshare_s3_touch_lcd_185b.c:947-987` 与它**逐参数相同**（`I2S_NUM_0` / `use_mclk true` / `hw_gain 5.0,3.3` / `mic_slot 0`）。`devices/AGENTS.md` 里也写明「the ES8311+ES7210 audio follows `board_vn_s3_183.c`」。

> 这块板没有屏、没有触摸、没有电量计，**是音频链路的最小复现体**。有「有字幕没声音 / 录音全是静音」时，先把 1.85B 的音频参数与它逐行对，再怀疑硬件。

### 4.3 AMOLED 三兄弟（1.75C / 1.75 / 2.16）—— QMI8658 与 PCF85063 的唯一官方线索

它们都带 QMI8658 + PCF85063，但 Muse 侧没接（走 Waveshare BSP，BSP 不含这两个）。官方 `AGENTS.md` 指向厂商例程：`examples/esp-idf/04_Immersive_block`（QMI8658）。**我们的 `muse_imu.c` 是自己写的，官方无可抄**，但厂商例程可用来核对寄存器配置（尤其 wake-on-motion 的 `0xFA IrqCtl` / `0xFE DisAutoSleep`，我们的板级注释里已经在用）。**【已确认】**

### 4.4 ESP32-S3-BOX-3 —— `box_3_microphone.c` 的「重建 ADC 配置」思路

该文件记录了一个真实坑：BOX-3 的静音开关会同时断 ES7210 供电和 I2S 输出，**解除静音后必须重建 ADC 配置**。我们没有静音开关，但同一个模式适用于我们的 **I2C 总线卡死自愈**：ES7210 掉线后重新 `es7210_codec_new()`，而不是只重发增益。**【高概率】**（同 codec、同失败模式）

### 4.5 圆屏排版：Watcher（412）/ StopWatch（466）/ LCD-1.28（240）

- 我们 360 圆用的是「常规布局 + 贴边图标」，与 1.85C 完全一致 → **直接对齐 1.85C 的 `muse_board_t` 字段即可**（`talk_hint = {LV_ALIGN_TOP_LEFT, 20, 16}` 我们已相同）
- `rim_controls`（26–36 px 贴边图标）是 466 屏的专用布局，360 上放不下，**不要抄**
- `round_area` 的圆屏裁剪对所有圆屏通用，见 §3.3

## 5. 官方的「插件」分层：什么该抄，什么不该抄

Muse 的板级架构是**一个结构体 + 一堆共享模块**（`muse_board.h`）：

```
muse_board_t  ← 每块板填一个（init / display_start / audio_init / poll_buttons / read_power / power_off …）
   ↑
   └── 共享层（与板无关，34 块板共用）：
        muse_ui.c  muse_voice.c  muse_audio.c  muse_settings*.c
        muse_lcd_bands.c（分带渲染）  muse_battery.c  muse_pmu.c
```

**该抄的（共享层，改一行会影响所有板，必须谨慎但可直接用）**
- `muse_lcd_bands.c` —— 分带 + 双 chunk 乒乓 + 超时自愈（`band never completed` / `chunk never completed`）。我们已用。
- `muse_audio.c` / `muse_voice.c` —— 录音/播放时序、`mic_slot` 语义、barge-in settle。
- `muse_battery.c` / `muse_pmu.c` —— 电量语义（`battery_pct = -1` 表示无电池）。

**不该抄的（板级差异，抄了反而错）**
- 1.85C 的 TCA9554 复位流程 —— 我们是直连 GPIO3/GPIO1，更简单，且已验证可用。
- 1.85C 的 ADC 电量分压 —— 我们有 BQ27220，精度更高。
- 466 屏的 `rim_controls` 布局。

**只能自己写的（官方 34 块板都没有）**
- `muse_imu.c/h` —— QMI8658A 抬腕唤醒（INT1=GPIO8）+ 翻面静音
- `muse_rtc.c/h` —— PCF85063A 的 UTC 语义、`Seconds.OS` 有效位、STOP 括号写
- BQ27220 接入（`espressif/bq27220 ^0.1.3` + 解封/DF 参数读）

## 附：一句话回答「有没有相似的板」

有，而且近到可以当同一块板用 —— **Waveshare ESP32-S3-Touch-LCD-1.85C**（官方正式支持）：同屏、同总线、同 15 根关键引脚、同 codec、同初始化表。它替我们验证了显示与音频两条最难的链路；真正需要我们自己扛的只剩 **BQ27220 电量计、QMI8658 IMU、PCF85063 RTC** 这三块官方从未做过的外设。
