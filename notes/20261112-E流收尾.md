# 1.5.3a E 流收尾（2026-11-12）

E 流是 1.5.3a 的最后一笔：音效两音（用户 2026-11-12 拍板）、版本号收口到 1.5.3a。金币雨倾斜标定不动（用户已确认方向是对的；符号 -1.0f 是 1.5.1 实机校验过的，增益/死区保持现状）。

## 1. 音效两音

都沿用 v4 的现滑合成与现有音量/喇叭开关，不新做静音 UI。

### ① 语音发送失败复用“坏”，只响一次

- 接在 `muse_voice.c` 的 `hold_rec(tried)`：`tried == true` 时响 `MUSE_SFX_BAD`。
- `tried` 的意思是这条语音已经 live 发往 Muse 且失败了（`finish_note()` 里 `hold_rec(s_tried)`，`s_tried` 只在 `go_live()` 里置真）。这时屏显 `SAVED, WILL TRY AGAIN`，音和字是同一时刻。
- 重试（`send_held()` 失败 → `SAVED NOTE: WILL TRY AGAIN` / `COULDN'T SEND A SAVED NOTE`）不经过 `hold_rec`，一律静音；离线保存（`tried == false`，屏显 `SAVED, SENDS WHEN ONLINE`）也不是失败，不响。
- “坏”用的是已落地的 v4 音（300→150 Hz 滑音、120ms、幅度 18000），不是方案稿最初写的 200→100 Hz/9000：2026-11-09 用户实听嫌太轻，已上移到 300→150 Hz、峰值抬到 18000（见 `muse_audio.h` 注释）。复用的是这个已调过的音，不改配方。

### ② 低电量 20% 以下两声 262Hz 哔哔

- 新音 `MUSE_SFX_LOW_BATT`（`muse_audio.h` 音符表）：262 Hz 两下，各 120ms，中间 80ms 静音间隔，共 320ms，幅度 7000。320ms 仍在 `MUSE_SFX_MAX_SAMPLES`（330ms，WIN）以内，播放缓冲不用改。
- 门在 `muse_battery.c`：`muse_battery_low_beep_due(p)`，纯状态机、不碰音频，主机测试直接驱动。逻辑：
  - 电量未知（-1）、USB 供电、正在充电 → 不响，并重新布防；
  - 电量 ≥20% → 不响，并重新布防；
  - 电量 <20% 且已布防 → 响一次，撤防；再低也不响，直到回到 20% 以上才重新布防。
  - 节流靠边沿门，不靠定时器：轮询是 2 秒（清醒）/10 秒（暂停），每 tick 调一次门也不会重复响。
- 接在 `muse_input.c` 的电量轮询处（`read_power` 成功后，`note_power` 之后）：`if (muse_battery_low_beep_due(&p)) muse_audio_sfx(MUSE_SFX_LOW_BATT);`。输入任务在任何屏态下都轮询电量，所以息屏时也会响；`muse_audio_write` 有互斥锁，和正在播的回复不抢采样。
- 残留盲区：电量计读数失败报未知 -1 时不响（没有可信的低电量信号，宁可不响）。

## 2. 版本号收口到 1.5.3a

按仓库既有做法（见 9b2e6de 1.5.2c、e66649c 1.5.2 两次收口）：

- `esp32/version.txt`：1.5.2 → 1.5.3a（无尾换行，保持原样）。
- `README.md`：页眉改成“正式版 1.5.2，最新测试版 1.5.3a”；更新记录新增 v1.5.3a 测试版条目，v1.5.2/v1.5.1 正式版条目保留。
- `ota/latest.json` **不动**：它是指向已发布正式版的 OTA 指针（b923afd 单独一笔指向 v1.5.2），等用户发 v1.5.3a 正式版时再改。
- 1.5.3a 以字母结尾，按 `project.cmake`/`validate_config.cmake` 的规矩就是测试版标记：Test 构建直接用，不补 `-test`；Release 构建会拒收带字母的版本。

## 3. 验收

- 全量主机测试：635 个（634 基线 + 1 个新增 `test_low_beep_due`），失败 27 + 错误 8 + 跳过 10；失败 27 行与基线逐行相同，错误 8 行与 D 流后一致，零新增。
- `test_sfx.py`：LOW_BATT 渲染 5120 采样、两下峰值 >1000、中间 1920..3199 采样全 0。
- `test_muse_battery.py` 新增 `test_low_beep_due`：一次低电量只响一次、回到 20% 重新布防、USB/充电/未知读数不响且重新布防、20% 本身不触发。
- 桩语法检查：`muse_battery.c`、`muse_input.c`、`muse_voice.c` 与 pristine 同一处失败（首个 IDF 头缺失），无新增问题。
- 中途抓到一个真缺口并补了：`hold_rec` 里新增的 `muse_audio_sfx` 调用让 D 流的 PTT 准入桩（`muse_ptt_admission_harness.c`，按字节编译生产版 `muse_voice.c`）链接失败（`undefined reference to muse_audio_sfx`），3 个准入测试没跑起来；已按桩里 `muse_audio_chirp` 的风格补了同款空桩，重跑后 33 个相关测试全过、全量回到 635 个。
- 未编译验证、未实机验收：本机无工具链；两声哔哔的听感与发送失败那声的实际响法，等用户真机验。
