## 二、Bug 清单（按严重度；★ = 已人工复核行号属实）

### 严重

1. ★ **`muse_audio_play.c:62-74` ensure_buffers 半初始化 → NULL 解引用**。`if (s_mp3) return true;` 只查一个指针；三连 malloc 部分失败时返回 false 但不清理，下次调用被 `s_mp3` 哨兵放行，`s_pcm/s_pcm16` 为 NULL 直接崩。修法：任一失败全部 free + 置 NULL；或哨兵改为三个指针都非空。
2. ★ **`muse_tts.c:140-155` + `457-470` barge-in 换代竞态毒化新回复**。旧 fetch 的 `ring_send` 在 3s 超时后无条件 `s_abort = true`，可覆盖新一代 `muse_tts_speak()` 清掉的 abort → 新回复全部数据在 `on_http_data` 被丢弃（静音）。另外 `xStreamBufferReset()` 在有任务阻塞于 buffer 时按 FreeRTOS 语义返回 FAIL，代码不检查 → 旧 MP3 残留混进新回复。修法：ring_send 置 abort 前校验代际（`s_fetch_gen == s_gen`）；cancel/speak 检查 reset 返回值。

### 中

3. ★ **`main/wifi_mgr.c:455-459`** `atomic_store(&s_sta_idle, false)` 后 `esp_wifi_connect()` 启动失败 `goto done`，无任何路径复位 → 之后每次 scan 入口白等 1s、connect 多付 500ms。修法：失败路径恢复 true。
4. **`main/wifi_mgr.c:254-297`** esp_event 回调里做重活：STA_START 同步 4 次 NVS 读 + dhcpc 操作；STA_DISCONNECTED 同步 `esp_wifi_get/set_config`。NVS 忙时拖住整个事件循环。修法：启动时预读配置进内存；set_config 挪到重连工作路径。
5. **`main/wifi_mgr.c:394-406/475/544/667-684`** `s_bssid_cache`/`s_channel_hint` 被 keeper 任务、扫描刷新、restart 多任务无锁读写 → 偶发锁错 BSSID 白等超时。修法：加互斥（仓库已有 s_cache_mutex 模式可复制）或收敛到 keeper 单任务。
6. **`main/wifi_mgr.c:512-518`** 自发断线 `schedule_reconnect()` 与用户 `wifi_mgr_disconnect()` 的 timer stop/start 命令顺序不保证 → 定时器存活后违背用户意愿重连。修法：`reconnect_timer_cb` 先复查 `s_keep_connected`。
7. **`muse_tts.c:457-470`** `muse_tts_cancel()` 不取走 `s_pending` 的 strdup 文本 → 之后不再有 TTS 请求时永久泄漏 ≤1KB。修法：cancel 在锁内取走并 free。
8. **`muse_interact_ui.c:1446-1455`（工作区新改动）** 每帧无条件 `refresh_status()` 对 7-8 个 label 反复 `lv_label_set_text`——LVGL 9.5 该函数**无同值短路**（每次 free+malloc 文本缓冲 + 重排版 + invalidate）。约 30fps × 8 label 的持续堆抖动。修法：照抄 `muse_menu.c:169` 的 strcmp 短路 set_text，或仅在 snapshot 变化时刷新。
9. **`muse_interact_ui.c:948-968`** PET_FEE 回执按"当前可见页"路由（`s_page == IC_PAGE_WHACKAMOLE`），但 snake 与 whackamole 共用 PET_FEE → 跨页竞态：误取消正常结算的打地鼠局；snake 被拒不回滚（白玩）。命令队列 8 深、worker 30s tick，积压时窗口真实。修法：回执带来源标记，或给 snake 补对称 cancel hook。
10. **`muse_input.c:1310-1341`（Test 构建）** `!strncmp(line, "alarm", 5)` 吞掉全部 `alarm*` 命令 → Test 固件里 `alarm.arm=N`、`alarm.stop`、`alarm.test` 全部落到"打印状态"分支，唤醒验收用例静默无效。两块对 `alarm=` 格式还不一致。修法：Test 块只精确匹配 `alarm=HH:MM:mask`。

### 低

11. **`muse_chat_session.cpp:2243-2249`** 6 条流的 `s_streams[i].line` 分配失败未纳入启动总校验 → hatch_task 照常启动，`feed_lines()` 首字节写 NULL 崩溃。修法：并入 ：2249 条件。
12. **`muse_chat_session.cpp:2216-2253`** 启动失败后 `s_cmds` 仍存在 → typed turn 的 `cmd.text` 入队无人消费，永久泄漏且调用方以为已发出。修法：失败时置 NULL（公开 API 均已判空）。
13. **`muse_audio_play.c:155-178`** 解码跟不上时丢数据但最终仍报 "played ok"（http_on_body 忽略返回值）。修法：置 `s_dropped` 标志，perform 结束后如实上报。
14. **`main/wifi_mgr.c:239-247`** 静态 IP 下 DNS 配置为空时无兜底（冷启动无租约可继承）→ 域名解析全挂且不自愈。修法：DNS 空时回退写网关。
15. **`muse_lcd_bands.c:339-346`** draw_bitmap 失败路径手动 `chunk_done()` 与在途 chunk 的 ISR 递减叠加 → 计数提前归零、band 重复 give（偶发撕裂 + 统计污染）。修法：失败时仅在无在途片时完成 band。
16. **`muse_lcd_bands.c:368-371`** register 失败路径泄漏队列/信号量/DMA 缓冲（仅启动期一次，备查）。
17. **`board_waveshare_s3_touch_lcd_185b.c:985-1012`** 触摸初始化失败连累整个 display_start() 返回 NULL → 触摸坏=完全无 UI 开机。修法：触摸失败降级为无触摸继续。
18. **`muse_chat_session.cpp:560-585`** `ws_upgrade()` 响应头缓冲无 NUL 终止，`atoi` 可能越界读（未定义行为）。修法：`hdr[have] = '\0'`。
19. **`muse_chat_session.cpp:2342-2377`** `muse_hatch_turn_caption()` 跨任务无锁读 `s_turn`（只读展示路径，最坏字幕短暂错乱）。
20. **`muse_sudoku_ui.c:333` + 各游戏文案** 硬编码 "20"、"5 金币" 不引用 `MUSE_SUDOKU_COUNT`/`MUSE_PET_GAME_STAKE`；`muse_whackamole.c:48` 局部数组 `int free[]` 遮蔽 libc free()。
21. **`muse_input.c:175-209`** 深睡前不取消 TTS/URL 播放，GOODBYE 被声音盖住（功能无害）。
22. **`muse_interact_ui.c:1471-1475`** feed 5s backstop 与迟到回执竞态：第二次喂食覆盖 `s_last_feed_*` 后，第一次回执用第二次的食物名判词。修法：backstop 置 skip 计数。

### 数独完成卡片（工作区新改动）

23. **`muse_sudoku_ui.c:389-394/497-506`** 快照失败（coins=0）时卡片显示"今日数独金币已满"语义错误（实为互动未就绪）；双完成竞态下第二次被 PET_CAP 拒却虚报 "+5 金币"。修法：快照失败显示"互动未就绪"；SOLVE 回执到达后按实际结果刷新。

### 4.2 可感知的交互统一（用户可见）
