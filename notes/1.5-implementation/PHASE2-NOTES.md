## 2. 从第 1 阶段改动的地方（用户 2026-10-25 晚拍板，照此执行）

### 2.1 UTC 日（`muse_pet_day()` 重写）

- 删掉 `localtime_r()` + `days_from_civil()` 路径（连同
  `<time.h>` 的 include），改成纯整数 UTC 日：
  `(now + MUSE_PET_DAY_OFFSET_SECONDS) / 86400`，其中
  `MUSE_PET_DAY_OFFSET_SECONDS = 0`（`muse_pet_model.h` 已有，
  第 1 阶段即定义，第 2 阶段未改其值）。
- **后果（必须让用户过目时确认）**：每日边界在**北京时间 08:00**
  （UTC 午夜），不是本地午夜。以后想改成本地午夜，只改该常量
  为 `8*3600`，不用改逻辑 —— 常量是单点，逻辑里没有第二处
  日期换算。
- `*calibrated` 现在只由 `MUSE_PET_TIME_MIN`（2025-01-01 UTC）
  决定：仍守生活费扣除与当日上限重置，**不再守占卜**（见 2.2）。
- `muse_pet_model.h` 顶部的“待验证 localtime”注释已删，换成
  UTC 日说明；第 1 阶段 NOTES §6 的 localtime 待验证项由此关闭，
  改为本 NOTES §8 的 UTC 边界实测项。

### 2.2 占卜删 `PET_TIME` 拒绝路径

- `muse_pet_model.h`：`PET_TIME` 枚举项已于第 1 阶段后删除
  （第 2 阶段开工时头文件已是删除后状态），`.c` 的占卜分支
  原先返回 `PET_TIME` 的代码已改成：**永远按当前 UTC 日抽/复用**
  （同日复用、新日抽新卡），不再区分“已校准/未校准”。
- 生活费的未校准守门**保留**（用户未反对该条）：
  `now < TIME_MIN` 时不扣、不重置当日上限。
- **预览版可接受行为（不是 bug）**：若 SNTP 随后跳变日期，
  下一次占卜按跳变后的 UTC 日抽新卡，可能一天内出现两张卡。
  占卜不再因此返回错误，也不再用旧卡顶替。

   `CONFIG_MUSE_POWER_TEST` / `CONFIG_MUSE_TELEMETRY`，

4. **小游戏随机唯一口径**：胜负随机只在 UI 点按时定

5. **饥饿/心情/能量字段保持删除**（版本号 2），不加回占位字段。
6. **未就绪/损坏文案以“互动”为准，不以设计 §5.3 草稿为准**：
   设计 §5.3 示例写的是“宠物未就绪 / 宠物数据损坏”，

## 3. 脸点按与字幕的接入点（`muse_ui_patch.md` 全文为准）

### 3.1 脸点按（双通道，`muse_ui.c` 的 `on_canvas_clicked()`）

- 同步通道不变：`muse_state_make_happy()`（1.6 秒开心）。
- 异步通道新增：守门全过才发 `PET_TOUCH`，顺序为
  IDLE → 脸 tile 可见（`muse_ui_face_active()`）→ 未息屏
  （`muse_ui_dark()`）→ 点不在脸控件上
  （`muse_ui_face_control_at()`，复用现有 speaker/aux 扩 12px 判定）
  → `muse_pet_request()` 非阻塞发送；失败只置
  `muse_interact_ui_touch_failed()`，由 tick 转成字幕，
  回调里不直接写字幕。
- 摸摸不在互动页里放按钮：脸点按是唯一入口。

### 3.2 字幕反馈接入（LVGL task，`muse_interact_ui_tick()`）

- tick 在 `frame_tick()` **最前面**调用（任何 early return 之前）：
  否则脸页不可见、滑动中、菜单/图片遮挡时 feedback 队列
  会攒满并卡住 worker（第 1 阶段：worker 在 feedback 满时停滞）。
- tick 顺序：排空 feedback（每条先刷 snapshot，文案数字全取
  快照）→ 刷 snapshot + 状态行 → 生活费公告（见下）→
  未就绪/损坏一次性公告 → 字幕过期清理 → 游戏动画推进。
- 字幕守门：只在 IDLE 写；过期 3 秒；清理前双重确认
  （当前字幕仍是互动字幕那条 **且** mode 仍为 IDLE），
  否则不碰对话字幕。**不要在 `muse_ui.c` 里另写一份过期清理**。
- 生活费：snapshot 的 `decay_notice > 0` 且 `decay_day` 未公告过
  且 IDLE 时，写“毛毛这几天花了 X 金币”并显示一次，
  **先显示、后发 `PET_DECAY_ACK`**（ACK 在前会让下一 snapshot
  的 notice 归零，金额就丢了）。`PET_DECAY_ACK` 本身不产生
  feedback（第 1 阶段设计），所以公告不依赖 feedback 循环。
- 互动 tile 内结果 note：不受 3 秒过期限制，离开 tile 时清掉
  （`muse_interact_ui_on_hidden()`，由 frame_tick 的
  `was_interact` 跟踪触发）；回来只显示状态行，不复活旧结果。
- 互动 tile 与字幕的关系：字幕标签在脸 tile 上，人在互动 tile
  上时看不到字幕 —— 所以每条反馈同时写 note（互动 tile 上可见）
  与字幕（回脸后可见），两者文案一致，缺一不可。

### 3.3 三 tile 后必改的两个陷阱（合入 review 重点）

1. **`muse_settings_ui_tick()` 的 visible 参数**：1.4d 传的是
   `lv_obj_get_scroll_x(s_tv) > 0`，二 tile 时等价于“在设置页”。
   三 tile 后脸在 (1,0)，该表达式在脸页也成立，必须改成
   `lv_tileview_get_tile_active(s_tv) == s_settings`，
   否则设置 UI 会在脸页也被 tick。
2. **frame_tick 的滑动静止判断**：1.4d 的
   `lv_obj_get_scroll_x(s_tv) != 0` 在二 tile 时等价于
   “脸不在屏上”。三 tile 后脸完全可见时的 scroll_x 是一个
   tile 宽（= `s_w`），照搬会让脸页永远 early return、脸动画冻住。
   改成 `!= s_w`，合入时实测滑动停稳后的 scroll_x 是否精确等于
   `s_w`（有 1px 级出入就改容差判断，不要硬等）。
3. **默认首页**：tileview 默认激活第一个 tile，三 tile 后第一个
   是互动 tile。必须在 `muse_ui_start()` 里显式
   `lv_tileview_set_tile(s_tv, s_face, LV_ANIM_OFF)`，否则设备
   开机停在互动页。

其余指针式逻辑不用改：`muse_ui_show_face()`、
`tile_changed_cb()`、`update_control_hints()` 的 settings 判定、
`s_bench_page` 段均为指针比较，坐标变化自动跟随。

### 4.2 喂饭子页（定稿参照 v18）

- 一排三个图片卡片：各 100×100，间距 8，整组居中（316px 宽），

### 4.3 小游戏子页（定稿参照 v17，Game-icons 白手图）

- 标题“小游戏” + 金币行（居中，y=84，与 snapshot 同步刷新）。
- 选择行：三张 100px 图片按钮并排（间距 8，整组 316px 居中，
  y=120），按钮内**只有手图、没有文字**；顺序石头 / 布 / 剪刀
  （按钮顺序）—— 注意口头禅顺序不同，见动画。
- 手图：Game-icons（CC BY 3.0，保留署名），整体逆时针转 90 度、
  手朝上；选择页约 100px、结果页约 130px；**同一套图**，
  不生成第二套（输家变暗是运行时 recolor，不是第二张图；
  赢家边框是容器边框，不是图的一部分）。
- 动画三段，总约 2 秒（不超 3 秒）：
  1. 出拳约 1 秒：字幕依次闪“石头！剪刀！布！”（每段约 300ms，
     注意这是口头禅顺序，不是按钮顺序），三张图 x 偏移 ±4px
     抖动约 3 次（166ms 一步），按钮变暗不可再点，无音效。
  2. 揭晓约 0.8 秒：两张 130px 手图并排（左你的、右毛毛的，
     占选择行槽位，选择行此时隐藏），赢的加 ACCENT 边框、
     输的白色换成 DIM 灰（recolor，不用不透明盖），平局都不
     高亮不变暗；下方一行结果字 + 连胜行（不要左右并排大字）。
  3. 结果页停住等点按：揭晓结束 → 手图隐藏、选择行回来、
     结果字 + 连胜行保留；点一张手就是下一局（先重查币 <5、
     再扣 5、再动画）；不自动跳走、不持 power lock。
- 结果字：赢绿（OK）“你赢了！”，输红（DANGER）“你输了”
  （**不要 error 抖动**），平灰（DIM）“平局，再来一局”。
- 胜负判定：UI 本地函数（布胜石、剪胜布、石胜剪），
  **模型不结算胜负**（模型只扣 5 币）；随机在点按时已定
  （`esp_random() % 3`），动画只是揭晓。
- 币不够：以点击前快照为准，<5 时不扣、不开局，字幕 +
  note 写“金币不够，先摸摸 / 喂饭”。
- 竞态处理：若 worker 反馈 `PET_POOR`（快照过期、实际币 <5，
  根本没扣），取消动画、恢复选择视图、不产生退款问题
  （因为没扣过）；若反馈 `PET_STORAGE`，同样取消动画并报
  “互动数据损坏”。
- 连胜与胜平负：**只记本局显示，不进 NVS**，重启清零。
  本阶段实现为会话级计数（离开游戏页不清零、重启清零）；
  若用户想要“每次进游戏页清零”，在 `on_hidden()` 里加
  一行清零即可，当前未做 —— 合入 review 时确认一次。
- 游戏页上看不到毛毛脸，不另画小脸画布；赢了附带调一次
  `make_happy()`（用户滑回脸时能看到开心，但游戏页本身
  不依赖脸表情）。

## 6. 接口与行为细节（合入 review 时对照）

- **回调只发动作**：三个主页按钮、喂饭食物、游戏出拳、运势按钮
  的回调都不结算、不直接改显示；显示只来自 snapshot +
  feedback。唯一例外是游戏动画的启动（点按时已定随机结果，
  但金币扣除仍以 worker 反馈为准，见 §4.3 竞态处理）。
- **喂饭“是否真给币”的判断**：`PET_OK` 只表示“已结算”，
  是否加币看 snapshot 的 `daily_feed_coins` 是否大于点击前的值
  （设计 §4.3）。`s_last_feed_before` 在发请求前从快照取值；
  若发请求时无快照，默认为 0 —— 此时若当日其实已领满
  （`daily_feed_coins` 已是 10），字幕会误写“+10 金币”。
  边界情况只在 worker 刚启动、快照未到时点喂饭，合入时
  可在无快照时先禁喂饭按钮，当前实现未禁（见 §7 待确认）。
- **串口命令行为不变**：`>pet.touch` / `>pet.feed` / `>pet.game`
  会真实改金币（第 1 阶段已说明，既有 bench 命令惯例如此）；
  串口喂饭的 feedback 也会走到本阶段的 drain，食物名取最近一次
  UI 喂饭的记录（若从未 UI 喂饭则为米饭），可能与串口实际喂的
  食物不一致 —— 串口验证时以金币数为准，不要以食物名文案为准。
- **不引入的东西**：IMU 手势、触摸唤醒、GPIO4 唤醒线、
  常驻扫描、高频轮询、power lock、音效、第二套 avatar 渲染。
  互动 tick 只在 LVGL 帧 tick 里跑，不阻止浅睡。

## 7. 合入前必核对点（编译时逐项打勾，不要跳过）
