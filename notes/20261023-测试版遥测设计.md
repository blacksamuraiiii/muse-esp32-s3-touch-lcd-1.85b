# 测试版诊断/遥测设计 v2（2026-10-23，官方优先修订版）

> v1 教训：第一稿跳过官方清单直接手攒（裸分区环形记录 = 重造磨损均衡、
> 还漏看已在仓库里的官方工具），本版先盘官方家底、只补真正的缺口。
> 用途不变：测试版能看功耗/传感器/状态时间线，正式版移除。

## §1 官方家底盘点（已逐项核实）

| 设施 | 出处 | 能干什么 | 对本任务的判定 |
|---|---|---|---|
| `muse_power_test`（ptest） | 上游 SDK，**fork 1.4b 已在仓**，Kconfig `MUSE_POWER_TEST`（Kconfig:217） | 台架功耗扫描：UART JSON 协议 arm/status/results；peripheral 与 sleep 两种矩阵，靠 VBUS 拔插边沿触发，外部电表读各状态电流；深睡恢复有 RTC journal | **台架定版工具**。它给"每个状态该耗多少电"的实测基线（如 REST 档整机电流），正是夜测异常的对照尺。定位是状态表征，不是整夜记录器 |
| `esp_pm_dump_locks()` + PM trace | ESP-IDF 官方 | 打印当前谁在持 PM 锁、锁的时长统计 | **"CPU 为啥不浅睡"的第一现场**，接个控制台命令即可，零新代码 |
| ESP Insights / esp_diagnostics | 乐鑫官方遥测框架 | 事件/指标进 RTC 环形缓冲（几十条量级），经 HTTPS/MQTT 上传乐鑫/RainMaker 云看板 | **查过不用**：① 传输是云端——夜里唤醒射频上传会污染功耗测量本身；② 设备数据出本地网络，与本项目数据不出户的惯例冲突；③ 缓冲量级是为崩溃取证设计的，装不下 7.5h、60s  cadence 的时间序列 |
| FATFS + wear_levelling（`fat` 分区） | ESP-IDF 官方组件/分区子类型 | 带磨损均衡与掉电一致性的本地文件存储 | **本地落盘的官方答案**，取代 v1 的裸分区自研环 |
| esp_coredump 分区 | ESP-IDF 官方 | 崩溃自动落盘 core dump | 与本设计正交，若未启用建议测试版顺带开 |

## §2 缺口（官方覆盖不到、才允许自写的部分）

只有一件：**应用状态时间序列的本地记录**——"几点几分、电量/平均电流/PS 档位/
状态位/浅睡占比是多少"，按分钟攒在机内、次日导出。Insights 是这件事的
云端版（已因上述理由排除），ptest 是台架版，都不覆盖整夜在机记录。
自写范围严格限定为一个采样器 + CSV 追加写 + 导出命令，存储/诊断全用 §1。

## §3 设计（v2）

### 3.1 三层分工
- **台架层（先行，基本现成）**：给 1.85B 板补 ptest 的板级胶头文件
  （上游只带 sensecap 的 `muse_power_test_board.h`，照它的结构填本板
  负载/引脚——这是板级适配，不是造轮子），开 `MUSE_POWER_TEST` 跑
  sleep 矩阵，产出各状态电流基线表，存进本文件附录
- **现场层（零新代码）**：控制台加 `>pmdump` 直调 `esp_pm_dump_locks()`；
  PS 切档日志已有，保留
- **夜测层（唯一自写件）**：`muse_telemetry.c` 采样器，如下

### 3.2 夜测采样器规格
- 存储：测试版分区表加一个 `fat` 分区（如 1MB，FATFS+WL 官方挂载），
  记录就是**纯文本 CSV 追加行**，人眼和表格软件直读，无格式解码器要写
- 周期行（60s）：`utc,pct,avg_mA,volt_mV,temp_C,ps(0/1/2),asleep,rest,
  alarm_armed,lightsleep_pct,wakes_delta`
  ——值全部来自现成 getter：电量计组件、`esp_wifi_get_ps()`、
  muse_state 状态位；浅睡占比用墙钟 vs tick 增量差估算（input 层验过的方法）
- 事件行（迁移即写）：开机（带唤醒原因）、PS 切档、进/出 REST、
  闹钟 arm/fire/stop/re-arm、关机前最后一条。同一 CSV 文件，首列标 P/E 区分
- 导出：`>telemetry.dump` 把文件走串口吐出（console.py 存盘）；
  `>telemetry.stats` 设备端算摘要（电流 min/avg/max、各档停留占比、
  浅睡占比均值、唤醒计数）；`>telemetry.clear` 删文件重建

### 3.3 移除形态（正式版）
- 单一 Kconfig `MUSE_TELEMETRY`（默认 n，测试版 overlay 开 y）门控模块
  与全部调用点（宏包裹，关即空展开）；FATFS 分区只在测试分区表里
- 测试版只能整片 USB 烧录不走 OTA（分区表不同），此点 v1 已述，沿用
- 版本号后缀 `-t` 防混淆，沿用 v1 §4/§6 的检查清单

### 3.4 铁律（沿用 v1，不变）
1. 采样开销目标 <0.1mA，首版做开/关对照夜测验证（电量计容量差）
2. 电池测试不依赖 USB 在线——机内攒、事后导，插线看实时日志的数据不作数

## §4 执行顺序

1. 补 1.85B 的 ptest 板级胶 + 跑 sleep 矩阵 → 状态电流基线表（台架，半天内）
2. `>pmdump` 接入（十分钟量级）→ 当场查一次夜里不睡的嫌疑
3. 夜测采样器（§3.2）→ 下一个夜测直接出时间线，与 1 的基线表对照定责
