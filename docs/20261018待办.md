## 1. 根因假设（按可能性排序）

### H1. I2C 毛刺改写 CTRL8（最可能）
tap 引擎生死只由 `CTRL8.bit0 (Tap_EN)` 控制，加速度计由 `CTRL7/CTRL2`
控制——两组独立寄存器，毛刺恰好改写 CTRL8 而不碰 CTRL7 是可能的。

毛刺来源：
1. `wait_buttons()` 进 light sleep 时，若 I2C 正在传输（200ms 轮询），
总线被截断，QMI8658 误解析为写寄存器。**`muse_imu_tap_tapped()` 和
`wait_buttons()` 无互斥，是竞态。**
2. BQ27220 (0x55) 定时读数，共享总线电平毛刺。

### H2. STATUS1 latch 假死（真 bug，但只解释"时灵时不灵"）
轮询只在 `muse_state_asleep()` 时跑。亮屏时敲击 → STATUS1=1、INT1=HIGH
没人读 → 引擎 latch 不再报新事件 → 下次睡时唤醒配 HIGH 但电平已满足。

### H3. Silicon bug（保底假设）
tap 引擎状态机卡死。H1/H2 排除后才考虑。

## 2. 诊断（按顺序做，每步都有明确判定标准）

### D1. 读回 CTRL8 确认配置漂移

在 `muse_imu_tap.c` 加：

```c
bool muse_imu_tap_config_ok(void)
{
uint8_t c8 = 0;
if (read_reg(REG_CTRL8, &c8)!= ESP_OK) return false;
uint8_t expect = CTRL8_HANDSHAKE_STATUSINT | CTRL8_TAP_TO_INT1 | CTRL8_TAP_EN;
if (c8!= expect) {
ESP_LOGW(TAG, "CTRL8 drift: got 0x%02x expect 0x%02x", c8, expect);
return false;
}
return true;
}
```

同时读回 `CAL1_L..CAL4_H (0x0B..0x12)` 共 8 字节，对比 init 写入值。

**判定**：
- CTRL8 变了 → H1 实锤 → 做 F1
- CTRL8 没变、CAL 没变、引擎仍不工作 → H3 → 做 F2
- 把读数值贴到进展记录，格式：`CTRL8=0x__ CAL=__ __ __ __ __ __ __ __`

### D2. 抓毛刺时间点（仅 D1 确认漂移后做）

在 `muse_imu_tap_tapped()` 进出和 `wait_buttons()` 进出打时间戳，
看配置丢失是否发生在 light sleep 进出 ±500ms 内。
是 → I2C/sleep 竞态实锤 → 做 F3。

## 3. 修复

### F1. 配置看门狗 + 自动重配

```c
// muse_input.c 轮询处：
if (muse_state_asleep() && now - s_tap_checked >= pdMS_TO_TICKS(IMU_TAP_POLL_MS)) {
s_tap_checked = now;
if (!muse_imu_tap_config_ok()) {
ESP_LOGW(TAG, "tap config lost, re-init");
muse_imu_tap_init(s_imu_dev); // 需把 s_imu 存成静态或传参
} else if (muse_imu_tap_tapped()) {
set_asleep(false, "tap");
}
}
```

注意：
- `muse_imu_tap_init()` 里已有 WHO_AM_I 校验，重跑安全
- 重配时先 `CTRL7=0x00` 停传感器（init 里已有），不会炸
- `s_imu` 的 device handle 需在 board init 里存下来给 input 用，
或把 handle 传给 `muse_imu_tap_init` 时内部保存（推荐后者，改动小）

### F2. 亮屏时也清 STATUS1

```c
// 把 asleep 条件去掉：
if (now - s_tap_checked >= pdMS_TO_TICKS(IMU_TAP_POLL_MS)) {
s_tap_checked = now;
(void)muse_imu_tap_tapped(); // 读即清，防止 latch；返回值只在 asleep 时用
if (muse_state_asleep() && <刚才读到的值>) {
set_asleep(false, "tap");
}
}
```

改法：让 `muse_imu_tap_tapped()` 的返回值存下来，asleep 判断只决定
是否调 `set_asleep`，不决定是否读 STATUS1。

### F3. I2C 与 sleep 加互斥

给 tap 的 I2C 读写加 mutex，`wait_buttons()` 进 light sleep 前拿锁。
改动较大，优先级低于 F1（F1 已能自愈）。

## 8. 电池电量恒显 100%（2026-10-18 新增）

症状：`read_power()` 读 BQ27220 的 `StateOfCharge (0x1C)` 永远 100%。

原理图已核：J1 电池 → VBAT_IN → 0.01Ω 采样电阻 → VBAT，
SRP/SRN 跨电阻测电流，走线正确，硬件没问题。

最可能原因（按序）：
1. **电量计没配过，跑 TI 出厂默认值**：BQ27220 上电时
   `RemainingCapacity = DesignCapacity`（默认值），SoC 天然 100%。
   没按实际电池写 DesignCapacity/化学体系就永远算不对。
   固件里只读 `0x1C`/`0x08`，从没写过配置。
2. **没跑过学习周期**：Impedance Track 要一次"充满→放电"才能学出真实容量。
3. 电流没测到（可能性低）。

### 诊断（读原始寄存器）
| 寄存器 | 地址 | 判定 |
|---|---|---|
| Voltage | 0x08 | 变不变（可对比万用表） |
| Current | 0x0A | 放电时是否为 0（正常应有几十~上百 mA） |
| RemainingCapacity | 0x0C | 剩多少 mAh |
| FullChargeCapacity | 0x10 | 跟电池标称对得上吗 |
| BatteryStatus | 0x16 | DSG 位（放电中？）、FC 位（满充？） |

- Current 恒 0 → 采样回路问题（查硬件）
- FullChargeCapacity 是离谱默认值 → 没配过，需写 Data Flash
  （DesignCapacity / DesignEnergy / 化学体系，按电池标称）
- Voltage 变、Current 有数、SoC 不动 → 跑学习周期：
  充满 → 拔线用到自动关机 → 再充满

需用户提供：电池标称容量（mAh），决定 Data Flash 写什么值。

## 9. 红色电源灯常亮（2026-10-18 新增，已定论）

原理图已核（DC-DC 区）：
- LED1（充电灯）：ETA6098 的 STAT 脚，充电红、充满绿
- **LED2（电源灯）：`3V3 → R1(10K) → LED → GND`，设备通电就亮**

结论：**纯硬件，固件管不了**。没有 GPIO、没有寄存器、没有配置项。
耗电 (3.3−2)/10K ≈ 130µA，可忽略。
想灭：黑胶带 / 拆 R1 或 LED2（烙铁）。不建议为省电折腾。

## 11. TTS 坏包丢弃验证（2026-10-18 新增）

现状：v1.1 加了 8 字节前缀闸门（`muse_tts.c` `gate_feed()`），
非 MP3（HTML 错误页等）整段丢弃、只留文字。但一直没实测过。

### 原理（已实现，无需改代码）
```c
// 前 8 字节攒齐后才判断：
static bool mp3_prefix_ok(const uint8_t *p, size_t n)
{
    if (n < 4) return false;
    if (p[0] == 0xFF) return true;              /* MPEG frame sync */
    return memcmp(p, "ID3", 3) == 0;            /* ID3v2 tag */
}
// 不通过 → s_payload_bad=true, s_abort=true, 整段丢弃，不重试
// 日志：muse.tts: bad MP3 payload len=N first=0xXX
```
