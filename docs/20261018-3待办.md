### 2.2 静态 IP（优先级最高）

- 现状：构建目录 `sdkconfig` 的 `CONFIG_HOMEHUB_STATIC_IP/…GATEWAY/…DNS` 全为空，
  SSID/密码/SDK token 也为空——这是"发版前清空凭据"留下的状态（见技能"发版与仓库卫生"）。
- 回填值（`~/muse-backup/sdkconfig-1.1-with-creds.txt` 留档的同款）：

```
CONFIG_HOMEHUB_STATIC_IP="10.168.2.85"
CONFIG_HOMEHUB_STATIC_NETMASK="255.255.255.0"
CONFIG_HOMEHUB_STATIC_GATEWAY="10.168.2.2"
CONFIG_HOMEHUB_STATIC_DNS="10.168.2.2"
```

- 生效位置：`main/wifi_mgr.c:151 apply_static_ip()`，挂在 `WIFI_EVENT_STA_START`；
  失败会自动退回 DHCP，不会失联。
- 风险：旁路由必须不把 .85 再租给别人（Kconfig help 已写明）。
- **根治（建议同批做）**：把这四个值改成运行期配置（NVS，配网/控制台可写），
  Kconfig 只当出厂缺省。这样以后发版照旧清空凭据，静态地址不会随镜像一起丢。
- 顺带加 `>net`：打印 IP/掩码/网关/DNS + 一次到网关与 `api.muse.ai:443` 的连通性，后续排障不用猜。

### 2.3 电池下敲击睡死

机制（代码级）：

| 位置 | 事实 |
|---|---|
| `components/muse/muse_input.c:452` | `bool want_low = pause && !muse_console_host();` |
| `components/muse/muse_console.c:42` | `muse_console_host()` = `usb_serial_jtag_is_connected()` |
| `components/muse/muse_input.c:367` | `set_cpu_low()` 只在 `want_low` 时 `light_sleep_enable=low` |

→ **插 USB 时永远不进 light sleep；拔线用电池才进。** 与用户观察"USB 正常、电池睡死"完全对上。
所以问题在 light sleep 路径本身，不在 tap 引擎配置（1.3 节已证配置没漂）。

已知可能的三条（按可测性排序）：

1. **I2C 事务被截断**：已有 `ESP_PM_NO_LIGHT_SLEEP` 锁（`muse_imu_tap.c:140/152`），
   但 `read_power()` 走 BQ27220 的 I2C 没有锁（`board_waveshare_s3_touch_lcd_185b.c:800`），
   Wi-Fi 与其他 I2C 设备也可能在睡醒边界被打断。
2. **唤醒源丢失**：`wait_buttons()` 每轮重新武装 GPIO8 电平唤醒（`muse_board.c:151-172`），
   武装与 light sleep 之间存在窗口；窗口内来的敲击只能靠 200 ms 轮询捞，而轮询本身依赖 tick 唤醒。
3. **整机睡死**（不只是敲不醒）：tickless idle 的定时唤醒失效时，任务永不再跑，表现为彻底无响应。

**必须先分清是 1/2 还是 3**，两条路修法完全不同。做法：

- 加 `>pmlow=1/0` 调试命令，强制带 USB 也进 light sleep（跳过 `muse_console_host()` 判断），
  这样能一边插着串口一边复现电池态。复现后看串口是否还在打日志、`>imu` 是否还应答：
  - 还在应答、只是敲不醒 → 1 或 2；
  - 日志停死、`>imu` 无应答 → 3，查 tickless/timer 唤醒。
- 顺手把 `read_power()` 的 I2C 也包上同一把锁（1 的补漏，代价小）。

- 看 `link.wifi: static IP 10.168.2.85 mask 255.255.255.0 gw 10.168.2.2 dns 10.168.2.2`
  与 `link.wifi: got IP 10.168.2.85`；
- 看 `link.noise_ctrl: session established` 与 `link.heartbeat: … ws=up`——通信恢复的判据；
- `>net` 一行记下网关与 DNS，作为后续对照基线。

**第三步：敲击**

- 带串口跑 `>pmlow=1` → 等自动息屏 → 敲击，按 2.3 的分诊表定位；
- 拿到结论再改代码，不先猜。
