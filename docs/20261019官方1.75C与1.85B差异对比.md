# 官方 1.75C 适配 vs 本仓库 1.85B 移植：逐模块差异对比（P0–P2）

> 对比基线：`upstream/main` = `f60347a`（含 `board_waveshare_s3_175c.c` / `board_waveshare_s3_185c.c`）
> 对比对象：`HEAD` = `d788f5b`（固件 1.3）
> 方法：`git diff upstream/main HEAD` 全量 + 板级文件逐行阅读 + 驱动源码核对（`managed_components/`）
> 结论分三级：**P0 必修**（功能错误 / 显示或功耗语义错误）、**P1 应修**（体验、功耗、可维护性）、**P2 记录**（一致性、文档、工具）

---

## 0. 结论先行

1. **P0-1：面板休眠命令是空操作。** `esp_lcd_st77916` 2.0.2 没有实现 `base.disp_sleep`，我们的 `panel_sleep()` 调 `esp_lcd_panel_disp_sleep()` 必然失败且返回值没人看 —— 息屏只关了背光，面板仍在刷新。1.75C 用原始 `0x10/0x11` 命令绕开了同一个坑。
2. **P0-2：缺 `round_area` 偶数对齐回调。** ST77916 驱动的 `draw_bitmap()` 不对坐标做对齐（已核源码），上游 1.75C 和 1.85C 都挂了 `LV_EVENT_INVALIDATE_AREA` 回调；我们没挂，局部刷新（字幕、时钟、进度条）会从奇数 x 起，QSPI 一次搬 2 像素，整行错位。
3. **P0-3：BOOT 上电时的按下状态没初始化。** 1.75C 有 `s_pwr.pressed = gpio_get_level(...)`，1.85C 有 `s_boot.pressed = ...`，我们没有；刷机时按住 BOOT 上电会被当成一次真实按下，长按可误触发「重置配对」。
4. 其余差异大多**由芯片决定、必须分叉**（AMOLED vs TFT、PMU vs 电量计、双键 vs 单键），判定为「合理差异」，不列为问题；真正需要盯的是**共享代码的连带影响**（`muse_lcd_bands.c` 的 flush 等待改动会作用于 1.75C/1.85C/2.16）。

## 1. 硬件差异矩阵（决定「哪些必须分叉」）

| 维度 | 1.75C（官方） | 1.85B（本板） | 代码是否必须分叉 |
|---|---|---|---|
| SoC / 存储 | ESP32-S3R8，**32 MB** flash / 8 MB octal PSRAM | ESP32-S3R8，**16 MB** flash / 8 MB octal PSRAM | 仅配置（分区/FLASH SIZE） |
| 面板 | CO5300 **AMOLED** 466×466，QSPI，亮度命令 `0x51` | ST77916 **TFT** 360×360，QSPI，亮度走 **LEDC PWM**（GPIO5） | **必须**：驱动、init 表、亮度、休眠命令、对齐 |
| 触摸 | CST9217（`bsp_touch_new`），与面板共用复位，深睡命令 `0xD105` | CST816S `0x15`，**独立复位 GPIO1 / INT GPIO4**，INT 低有效脉冲 | **必须**：复位、唤醒策略、休眠语义 |
| 电源 | **AXP2101 PMU**（I2C），按键锁存、真断电 | **BQ27220 电量计**（`0x55`），无 PMU，关机靠 deep sleep | **必须**：读电量、关机、按键来源 |
| 按键 | PWR（GPIO3，经 BSS138 反相，高有效）+ BOOT | 仅 BOOT；**PWR 是纯硬件电源键，固件读不到** | **必须**：按键表、提示位置、aux 语义 |
| 音频 | ES8311 + ES7210，走 Waveshare BSP | 同一套 codec，**手写 I2S0 + MCLK=GPIO2**，`pa_pin=GPIO9` | 半必须：引脚不同，通路结构可复用 |
| 传感器 | 无 IMU / 无 RTC | QMI8658A（`0x6B`，INT1=GPIO8）+ PCF85063（`0x51`） | 本板新增（上游无对应实现） |
| 屏幕形状 | 圆 466（`rim_controls` 专用布局） | 圆 360（沿用常规 360 布局 + 贴边图标） | 必须：UI 参数不同 |

> 结论：**板级文件分叉是合理的**。真正该对齐的是「板级抽象层之外的共享代码」以及「上游已踩过、我们漏掉的板级细节」。

## 3. P0（必修）

### P0-1 面板 SLPIN/SLPOUT 实际没发出去

**证据**
- `managed_components/espressif__esp_lcd_st77916/esp_lcd_st77916_spi.c` 只注册了 `del / reset / init / draw_bitmap / disp_on_off`，**没有 `base.disp_sleep`**。
- `board_waveshare_s3_touch_lcd_185b.c:880-888` 用 `esp_lcd_panel_disp_sleep(s_panel, sleep)`，返回值被丢弃 → 空操作。
- 对照：`board_waveshare_s3_175c.c:177-181` 用原始命令 `(0x02<<24)|(0x10|0x11)<<8` 自己发；`board_waveshare_s3_185c.c:304-308` 同样调 `disp_sleep`（**上游 1.85C 有同一个坑**）。

**后果**：电池态「熄屏」只把背光拉到 0，ST77916 仍在内部振荡刷新（典型 10–20 mA），500 mAh 电池待机时间被腰斩。

**修法**（`board_waveshare_s3_touch_lcd_185b.c`）
```c
/* 文件顶部加：面板 IO 要留给休眠命令用 */
static esp_lcd_panel_io_handle_t s_panel_io;

/* display_start() 里，重建 40 MHz IO 之后补一行 */
s_panel_io = io;

/* 替换 send_panel_sleep / panel_sleep */
static void send_panel_sleep(void *sleep)
{
    /* ST77916: 0x10 SLPIN / 0x11 SLPOUT，QSPI 命令路径 opcode 0x02 */
    bool in = *(bool *)sleep;
    esp_lcd_panel_io_tx_param(s_panel_io, (0x02u << 24) | ((in ? 0x10u : 0x11u) << 8), NULL, 0);
}

static void panel_sleep(bool sleep)
{
    muse_lcd_bands_run(send_panel_sleep, &sleep);
    vTaskDelay(pdMS_TO_TICKS(120));   /* 与 1.75C/1.85C 一致：SLPOUT 后要等 */
}
```
**验收**
- 串口无 `esp_lcd_panel_disp_sleep` 相关错误；
- 电池态息屏 30 s 后测 VBAT 电流，应从 ~20 mA 量级降到个位数 mA；
- 唤醒后首帧不丢（`muse_lcd_bands_run` 已保证命令与绘制同任务）。

> 关联：1.75C 关机靠 PMU 真断电，不存在「深睡残留电流」这一整类问题；我们靠 deep sleep，所以除了 SLPIN，**功放使能 PA 拉低、BOOT 唤醒脚的 RTC 上拉**也要一起处理（详见 `docs/20261019代码审查.md` 的 P0 条目）。三项合起来才是「关机真的不耗电」。

### P0-2 缺偶数对齐回调，局部刷新会错位

**证据**
- `esp_lcd_st77916_spi.c:473-498` 的 `draw_bitmap()` 直接把 `x_start/x_end` 写进 CASET，**不做奇偶对齐**。
- `board_waveshare_s3_175c.c:91-96,137` 与 `board_waveshare_s3_185c.c:101-107,261` 都挂了 `round_area` + `LV_EVENT_INVALIDATE_AREA`。
- 我们的 `display_start()`（`board_waveshare_s3_touch_lcd_185b.c:691-864`）**没有该回调**（`grep round_area` 无命中）。

**后果**：QSPI 一次搬 2 像素，奇数 x 起始的局部区域整行偏移 1 像素 —— 字幕、时钟、进度条边缘出现串色/抖动，整屏重绘时看不出来，容易被误判成「屏幕质量问题」。

**修法**（放在 `muse_lcd_bands_register()` 成功之后、触摸初始化之前）
```c
/* ST77916 的 QSPI 每拍两个像素：更新窗口必须偶数对齐（同 1.75C/1.85C）。 */
static void round_area(lv_event_t *e)
{
    lv_area_t *a = lv_event_get_param(e);
    a->x1 &= ~1;
    a->y1 &= ~1;
    a->x2 |= 1;
    a->y2 |= 1;
}
...
lv_display_add_event_cb(disp, round_area, LV_EVENT_INVALIDATE_AREA, NULL);
```
**验收**：让一行中文字幕连续刷新 30 s，左边缘无 1 px 串色；`>` 控制台开一次 OTA 进度条观察右端。

### P0-3 上电时 BOOT 的按下状态未初始化

**证据**：`board_waveshare_s3_touch_lcd_185b.c:631` 直接 `return muse_gpio_button_init(&s_talk, TALK_GPIO);`；1.75C 在 `:71`、1.85C 在 `:154` 都有 `pressed = gpio_get_level(...)` 的初值处理。

**后果**：刷机/复位时按住 BOOT，固件认为「刚刚按下」；持续 5 s 会走到 `reset setup`（解绑 + 忘 Wi-Fi），这是会丢配置的操作。

**修法**
```c
esp_err_t err = muse_gpio_button_init(&s_talk, TALK_GPIO);
if (err == ESP_OK) {
    /* 刷机时 BOOT 常被按住：别把「已经按着」算成一次按下。 */
    s_talk.pressed = gpio_get_level(TALK_GPIO) == 0;
}
return err;
```
**验收**：按住 BOOT 上电，串口无 talk press、无 `reset setup`；松开再按才有 PRESS。

## 6. 建议的回流（上游贡献）切分

**适合回流**
1. P0-1（`disp_sleep` 缺失）——**上游 1.85C 同样中招**，是干净的 bug fix。
