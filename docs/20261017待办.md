## 1. GitHub OTA（今天主线）

### 抄谁的
timmy2048 的 `patches/muse-185b-ota-menu.patch` + `ota/publish_github.sh`
（本地对比目录：`~/workspace/gadget-compare/timmy2048/`）。

### 原理
- 固件里嵌版本号（`esp_app_desc`），设置菜单加"检查更新"
- 板子拉 `https://github.com/<你>/muse-esp32-s3-touch-lcd-1.85b/releases/latest/download/latest.json`
- `latest.json` 内容：`{version, url, sha256, size, notes}`
- 有新版 → 进度条下载 → 校验 sha256 → 切 OTA 分区 → 重启

### 步骤
1. 把 `timmy2048/esp32/main/ota.c`、`ota.h` 拷进你仓库的 `esp32/main/`，
   在 `CMakeLists.txt` 里加进编译
2. 应用 `muse-185b-ota-menu.patch`（设置菜单入口；有冲突就手改，
   入口函数名对照你的 `muse_menu.c` 调整）
3. 复制 `ota/publish_github.sh` 到你仓库根，改 `REPO=` 为你的仓库名
4. 发版流程：
   ```sh
   # 改 esp32/version.txt，构建时 -D PROJECT_VER=xxx 保持一致
   tools/muse/board.sh build lcd185b
   ./ota/publish_github.sh build-muse-lcd185b/muse-gadget.bin 999.1.6 "更新说明"
   ```
5. 板端验证：设置 → 检查更新 → 看进度条 → 重启后版本号变化

### 注意
- 仓库必须是 Public（固件里不带 token 拉 Release）
- 发布脚本会校验 bin 里嵌的版本号和输入的 label 一致，不一致拒绝发布
- NVS 不动，配对和 Wi-Fi  survive OTA

## 2. TTS 加固：严格 MP3 校验

### 为什么
之前无声的根因之一：TTS 服务返回错误页面（HTML）时，固件可能把
HTML 当 MP3 喂给解码器。timmy2048 的 `TTS_NOSOUND_FIX.txt` 确认过
（有道返回 HTTP 500 + 120 字节错误页）。

### 改哪里
你的 `esp32/components/muse/muse_tts.c`，在拿到 HTTP 响应后、送解码器前加：

```c
// 严格 MP3 校验：HTTP 2xx + 长度>64 + MP3 同步字节或 ID3 头
static bool mp3_looks_valid(const uint8_t *data, size_t len)
{
    if (len <= 64) return false;
    return (data[0] == 0xFF) || (len >= 3 && memcmp(data, "ID3", 3) == 0);
}
```

- 校验失败 → 按原有逻辑降级为纯字幕（别播，别崩）
- 日志打一行 `muse.tts: bad MP3 payload len=%d`，方便以后排障

### 另外建议
- HTTP 请求加浏览器 User-Agent（有些 TTS 服务挡非浏览器 UA）
- URL 编码用 percent-encode，别用 `+` 代替空格（`+` 在 query 里会被解成空格）

## 3. 敲击唤醒（QMI8658 tap 中断）

### 为什么是敲击，不是抬腕/计步
- 抬腕/计步：IMU 持续采样 + ESP32 轮询，费电
- 敲击：QMI8658 芯片内 tap 检测引擎，配好寄存器后它自己判断，
  检测到才拉 INT 引脚。ESP32 进 light sleep 睡着等 GPIO 中断，
  平时几乎不耗电

### 三步
1. **查 INT 脚**：翻 1.85B 原理图，确认 QMI8658 的 INT1/INT2 接到
   哪个 GPIO（板文件里只写了 I2C 地址 0x6B）
2. **配 tap 寄存器**：阈值、时间窗口、使能 INT 输出
   （翻 QMI8658 datasheet tap 章节；微雪官方 `06_qmi8658_test`
   只有轮询示例，没有中断示例，得自己写）
3. **ESP32 侧**：GPIO 唤醒源 + light sleep，tap 中断到 → 亮屏

### 交付物（我可以写）
`esp32/components/muse/qmi8658_tap.c` / `.h`：
- `qmi8658_tap_init()`：配 tap 检测 + INT
- `qmi8658_tap_enable_wake()`：进 sleep 前调用
- 中断回调里亮屏（调现有唤醒路径）

## 4. 音量按钮左移

### 位置代码
`esp32/components/muse/muse_ui.c` → `build_answer()`（约 697 行）：

```c
int spk_r = (SPEAKER_PX + SPEAKER_GROW_PX) / 2;  // (64+8)/2 = 36
int spk_x = -s_w / 2 + 8 + spk_r, spk_y = -s_h / 2 + 8 + spk_r;
if (muse_board->round) {
    spk_y = -ring_in * 5 / 8;
    int d = ring_in - spk_r - 4;   /* just inside the ring, even when swollen */
    spk_x = -(int)sqrtf((float)(d * d - spk_y * spk_y));
}
```

`spk_x` 为负即左侧。当前贴着圆环内圈放（`-4`），头像大就挡上。

### 改法
把 `-4` 改成 `-24`（往左挪 20px），或按实际遮挡微调：

```c
int d = ring_in - spk_r - 24;
```

- `SPEAKER_PX 64`：按钮直径，别改
- `SPEAKER_GROW_PX 8`：按住膨胀量，别改
- 按钮的点击/长按/动画在 `build_speaker()` 里，位置独立，改坐标不影响逻辑
- 改完重编刷机（有了 OTA 之后直接推 Release）
