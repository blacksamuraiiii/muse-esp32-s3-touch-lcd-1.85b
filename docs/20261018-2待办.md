## 1. QMI8658 软件复位（5 分钟，优先级最高）

### 为什么
你的 `muse_imu_tap_init()` 上来就写 CTRL1/CTRL8/CTRL9，
**从来没复位过芯片**。QMI8658 上电后的寄存器状态不确定，
tap 引擎跑一阵"永久死亡"很可能与初始状态脏有关。
wupsbr 的 `muse_imu.c:configure()` 第一件事就是软件复位。

### 改法
在 `esp32/components/muse/muse_imu_tap.c` 的 `muse_imu_tap_init()` 里，
WHO_AM_I 校验通过后、写 CTRL1 之前，加：

```c
/* Datasheet Rev A §寄存器表：RESET=0x60，写 0xB0 触发软件复位。
 * wupsbr 的 muse_imu.c 也是这么做的；复位后等 20ms（datasheet 标 15ms）。 */
#define REG_RESET 0x60
#define RESET_CMD 0xB0

err = write_reg(REG_RESET, RESET_CMD);
if (err != ESP_OK) {
    return err;
}
vTaskDelay(pdMS_TO_TICKS(20));
```

注意：
- `write_reg` 和 `vTaskDelay` 在该文件里都已可用（FreeRTOS.h 已 include，
  如没有则补 `#include "freertos/task.h"`）
- 复位会清掉所有寄存器，所以必须放在**所有配置之前**
- 复位后 WHO_AM_I 不变（0x05），不需要重校验

### 验证
刷机后串口确认无报错，跑 `tap_cycles.py`：
- 如果之前"刷机后能用、过阵死"，看死亡时间是否推迟或消失
- 单独这一项不一定根治（待办一里的 D1/F1 还是要做），但属于"没坏也该修"的 hygiene

## 2. Display freeze fix（上游 PR #34，你的仓库没有）

### 为什么
LVGL 刷屏时等 band 发送完成用的是**空转自旋**。当 LVGL 任务因持有 mutex
被 FreeRTOS 临时抬到高优先级，自旋会永远 starve 发送任务，
band 卡在队列里，**屏幕约 20 分钟后冻住**。
wupsbr 从上游 PR #34 cherry-pick 了修复；你的
`esp32/components/muse/boards/muse_lcd_bands.c` 还是旧版。

### 改法

## 3. 混合敲击方案（思路，待办一的保底路线）

### 背景
wupsbr **根本不用 QMI8658 的硬件 tap 引擎**：
`muse_imu.c` 以 1kHz 轮询加速度计，软件里减重力、检测摆动
（`muse_imu_poll_shake()`）。没有 CTRL8/CTRL9/CAL，没有 INT 引脚，
没有 STATUS1 latch——你的"引擎永久死亡"类问题天然不存在。

但它要求 CPU 醒着轮询，不适合你的 light sleep 唤醒。
折中方案：

### 混合方案
```
light sleep
  │
  ├─ GPIO8 (INT1) 高电平唤醒 ← 硬件 tap 引擎只当"门铃"，不读 STATUS1
  │
  ▼ 醒来后
软件确认：连读 N 个加速度计采样（0x35..0x3A），
  看有没有敲击特征（Z 轴突跳 > 阈值，如 0.5g，50ms 内回落）
  │
  ├─ 是真敲击 → set_asleep(false, "tap")
  └─ 是噪声/误触 → 回去继续睡
```

### 为什么比现在可靠
| 环节 | 现在 | 混合方案 |
|---|---|---|
| 唤醒源 | INT1 电平 + 200ms 轮询读 STATUS1 | INT1 只管叫醒，不读 STATUS1 |
| 确认 | STATUS1.bit1（引擎说了算） | 软件看加速度计波形（自己说了算） |
| 引擎死了 | 彻底没戏 | INT1 可能也不跳了…（见下） |

### 局限（诚实说明）
如果 tap 引擎"永久死亡"是 INT1 引脚都不跳了，那混合方案也救不了，
因为叫醒都叫不醒。这种情况下要换**定时唤醒轮询**：
light sleep 改成"GPIO8 **或** 定时器 200ms"唤醒，
每次定时醒来读加速度计做软件检测，无敲击就回去睡。
代价是每 200ms 醒一次，功耗高于纯 INT 唤醒，但比一直亮屏低两个数量级。

### 实施顺序建议
1. 先做待办一的 D1/F1（配置看门狗）+ 本待办的第 1 项（软件复位）
2. 如果 tap 还是死 → 上混合方案（软件确认）
3. 如果 INT1 都不跳了 → 定时唤醒轮询（保底）

### wupsbr 软件检测核心逻辑（参考）
`muse_imu.c:muse_imu_poll_shake()`：
- 维护 `s_gravity[3]`（一阶低通，alpha=0.06）
- 每采样算 `d = a - gravity`，`g = |d|`
- `g > 阈值` 进入 swing，方向反转或回落则计一次 swing
- 3 次反向 swing 在时间窗内 → 判定为 shake

敲击检测可简化：单次 `g > 0.5g` 脉冲即算 tap，不需要 3 次 swing。
阈值按你的 PeakMagThr=800 LSB（2g 量程下约 0.05g？按实际调）对齐。
